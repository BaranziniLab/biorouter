Getting started

Install the app, connect a model and start a chat. These docs describe biorouter v{{LATEST_VERSION}} on Windows, macOS and Linux.

Install

Download the file for your computer from the Download page or from GitHub Releases.

  • Windows x64. Biorouter-Setup-*.exe is the installer. A later one upgrades in place and keeps your shortcuts. A .zip of the same build is also published.
  • macOS. Open the .dmg for your Mac, arm64 for Apple silicon or x64 for Intel, and drag Biorouter to Applications.
  • Linux, Debian and Ubuntu. Run this in the folder that holds the file: 
    sudo apt install ./biorouter_*.deb
  • Linux, Fedora and RHEL. Run this in the folder that holds the file: 
    sudo dnf install ./Biorouter-*.rpm
  • Linux server. The biorouter-cli packages, one .deb and one .rpm, install the command line, the background service and the browser interface with no desktop app. Install one the same way. See Command line.

The app checks for new releases and tells you when one is ready. Settings → App → Updates shows where it stands.

When it starts, the app checks for Git, Python, uv and npm, which some extensions use, and offers to install any that are missing. The app itself runs without them. Local models on Linux need Debian 12, Ubuntu 22.04 or newer.

Install the command line

The desktop app includes the biorouter command line tool, which shares your settings and chats with the app. When the command is not on your PATH, the app offers to install it as it starts. On Windows and on the Linux desktop packages, use that prompt. On macOS you can also run the bundled copy once from a terminal:

/Applications/Biorouter.app/Contents/Resources/bin/biorouter \
  setup-path

setup-path, which the app's prompt also runs, links the command into a folder on your PATH, such as /usr/local/bin or ~/.local/bin. On Windows it copies it to %LOCALAPPDATA%\Biorouter\bin. If the folder is not on your PATH yet, it prints the line to add. Open a new terminal and run biorouter info to check.

After an update, the app offers to update the command when the copy on your PATH is older. The Linux server packages install biorouter to /usr/bin and need no setup.

Connect a model

Biorouter asks you to choose a model the first time it opens. To add or change one later, open Settings → Models → Configure providers. Providers sit on three tabs.

  • Local. Llama Server needs nothing installed. The first time Biorouter opens, its row lists models: pick one and choose Download & run. The model downloads once; after that it runs on this computer, so your messages never go to a model host. Later, Settings → Models → Local Model Inventory downloads more. Ollama needs Ollama running on this computer with a model pulled.
  • Institutional. For UCSF. Versa API Azure asks for your Versa API key. Versa API Bedrock asks for your Versa access key ID and secret access key. The endpoints are set for you.
  • Public. Claude Code and Codex use the vendor's command line tool, installed and signed in to your own plan; Biorouter never sees the credential. Anthropic, OpenAI and Google Gemini need an API key from that provider. The others ask for that provider's own key or account credentials.

Choose a provider's row, then Configure, and enter its credentials. Biorouter checks them when you save. From a terminal, run biorouter configure and choose Configure Providers. Models and providers lists every provider and its default model, and Security explains where credentials are kept.

Llama Server, Ollama running on this computer, and the two Versa providers are private. Ollama on another machine, and every other provider, is public. For patient data, use a private model. Once a chat uses a private model or a private data extension, it stays private, and Biorouter refuses to switch it to a public model. To change that, choose Make this chat public in Chat history, or run biorouter session declassify. See Private and public.

UCSF researchers: use the two Versa providers on the Institutional tab. Azure OpenAI and Amazon Bedrock on the Public tab stay public even if you point them at a UCSF endpoint, because Biorouter cannot check where they send data.

Start a chat

  1. Open a new chat Choose New chat in the sidebar, or press Cmd+T (Ctrl+T on Windows and Linux).
  2. Pick a working folder The folder chip above the text box is where the agent reads and writes files. Choose it to switch folders before you send the first message. After that the chat keeps it.
  3. Ask Type a request in plain language and press Enter, for example “List the files in this folder and summarize the README.” The agent answers and shows each tool it runs as one line.

From a terminal, biorouter session opens an interactive chat, and biorouter run -t "Summarize ./notes.md" sends one request and exits.

Where your data lives

Biorouter keeps its settings and chats as files on your computer. The app and the command line share them. On macOS and Linux:

  • Settings. config.yaml in ~/.config/biorouter/
  • Chats. sessions.db in ~/.local/share/biorouter/sessions/
  • Logs. ~/.local/state/biorouter/logs/

On Windows they sit under %APPDATA%\Block\biorouter\. Run biorouter info to print the paths on your computer. Configuration lists every file.
