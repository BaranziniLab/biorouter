Knowledge bases

A knowledge base is a folder of linked pages that the agent writes from your papers, files, links and notes.

What a knowledge base is

Each base is one folder with its own git history, at ~/.config/biorouter/knowledge/<id>/. The sources you add and the pages the agent writes are kept apart, so a page can always be traced to the file it came from.

PathWhat it holds
raw/<source>/Each source as you added it, its Markdown conversion (source.md) and meta.yaml: title, link, checksum and credibility grade.
knowledge/<type>/The pages the agent writes, one per concept, filed by type. Each page starts with a short YAML header that names its type.
index.md, log.mdA catalog of the pages and a change log, both kept by the agent.
schema.mdHow this base is written. The agent reads it on every run, and you can edit it.

A base stays on your disk. Its only network calls are credibility lookups (Crossref and OpenAlex), the links you ask it to fetch, and the model that digests your sources. Git is built in; you do not need it installed.

Create a base

  1. Open Knowledge Open the sidebar's Components group and choose Knowledge.
  2. Start a new base Choose the base's name at the top of the view. In the menu that opens, choose Create knowledge base…
  3. Name it and pick a format The format decides how pages are written and checked. Then choose Create knowledge base.
ChoiceFormatUse it for
General knowledgeOKFNotes, project context and anything that is not curated biology. Any page type and any link name; nothing is rejected.
Curated biomedicalBioOKFBiomedical literature, or a base another institution will read. The vocabulary is checked, and every link names its evidence.

The format is fixed when the base is created. The dialog says so: “You cannot change a knowledge base's format yet.” A base from an older version keeps working and is marked Legacy. biorouter knowledge create makes an OKF base; to make a BioOKF base, use the app or ask the agent.

The BioOKF vocabulary

BioOKF v0.5 is a strict biomedical profile of the Open Knowledge Format (OKF v0.2). A page's type is one of 28: 20 biomedical entity types, such as Gene, Variant, Disease and CellType, and 8 provenance and context types, such as Publication, Study and Dataset. A typed link uses one of 35 predicates: 24 positive predicates such as causes and treats, and 11 negations such as not_treats. Every link names its evidence: a knowledge level, an agent type and a primary source page. A value outside the vocabulary is flagged with the closest legal one.

Visible bases and the primary

Every base is visible to a chat unless you hide it. When the agent searches without naming a base, it searches all the visible bases and says which base each result came from.

One visible base is the primary: where the agent writes when no base is named, the base it reads by default, and the base the Knowledge view shows. Soul is the primary until you choose another.

  • Hide a base from a chat. Choose the knowledge chip under the text box. Each base has a switch, and Hide all or Show all sets them together. A hidden base stays on disk.
  • Change the primary. In the Knowledge view, choose the base's name at the top and pick another base. Manage bases… lists every base with its format, its privacy and a switch that includes it in the chat.
  • Point one message at a base. Type / in the composer and pick it, or write /kb:ID.

If you hide the primary, the next visible base takes its place. If you delete it, the chat has no primary until you choose one, and a write that names no base is refused with the list of bases to choose from.

Add sources

Open a base in the Knowledge view. Sources sit beside the graph; in a narrow window they are the Sources tab.

  1. Stage sources Drop files or folders on the dropzone, or choose it to browse. Folders and archives are unpacked, and each readable file is staged on its own. Paste text takes notes or an excerpt, and offers any links in it as sources of their own.
  2. Check the model The panel shows the model this base digests with. Change it there.
  3. Choose Digest staged sources Progress streams in as pages are written. Stop ends the run.

Readable formats: PDF, Word (.docx), PowerPoint (.pptx, speaker notes included), Excel and OpenDocument spreadsheets (.xlsx, .xls, .ods), CSV, HTML, Markdown and plain text. Save an old .ppt as .pptx first. A scanned PDF with no text layer ingests with a warning.

In a chat, ask the agent to add files, folders or links to a base. It runs the same pipeline and reports any source it could not digest. It can also digest past chats into a base.

Conversion runs once. It also grades the source's credibility, and its result is kept. The digest is a subagent that works from that Markdown, never the original file. It reads the base's schema.md and the pages it may change, writes a page for the source, updates related pages and links them. If it fails, its changes are rolled back and the raw source is kept so you can try again.

The graph

The Graph draws each page as a node and each link as an edge. Choose a node to inspect its page. Type is the fill, credibility is the ring.

  • Fill. In a BioOKF base each of the 28 types has its own color, grouped into seven families: genomic, molecular, anatomy, clinical, exposome, physical and provenance. Provenance types are drawn as open circles, so the evidence stands apart from the science. In an OKF base the color comes from the type's name.
  • Ring. A source's ring counts its credibility in arcs, from four for peer reviewed to one for gray literature. Web and personal sources have a dashed ring and a retracted source a solid one. The legend groups them as Well sourced, Weakly sourced, Not academic and Retracted.

Biorouter grades each source when it is converted. It looks for a DOI and checks it with Crossref, then OpenAlex, then checks the host, then looks for journal markers in the text. When none of these answers, the model grades it.

TierRingHow it is detected
Peer reviewed4 arcsA DOI resolves to a journal article, or the text carries clear journal markers.
Book3 arcsCrossref or OpenAlex report a book or a chapter.
Preprint2 arcsA preprint server such as arXiv, bioRxiv or medRxiv, or a DOI registered as a preprint.
Gray literature1 arc.gov and .edu hosts, WHO, CDC, NIH, FDA, ClinicalTrials.gov, EMA and standards bodies.
WebDashedAny other page.
PersonalDashedPasted text with no stated source.
RetractedSolidCrossref or OpenAlex mark it retracted, whatever its tier.

A graph with nodes and no edges means the pages hold no links, and a lint reports each of them as an orphan.

Search, history and restore

  • Search. The agent searches the pages by keyword (BM25), and the original source text when you ask for it. In a chat it reads the pages it finds and answers from them.
  • History. Every change is a git commit tagged by kind: ingest, link, flag, query, lint, restore or manual. Change log, in the base's ⋯ menu, lists them, and log.md keeps the same record.
  • Restore. In the change log, Preview shows the base as it was at a commit, and Restore adds a new commit that returns the base to that point, so a restore can itself be undone.

Export and import

Export as .brkb, in the base's ⋯ menu, writes the whole base to one file: pages, original sources and git history. To bring one in, open Manage bases… and choose Import from .brkb. The import keeps its id, or takes a numbered suffix if that id is in use, so it never replaces a base you have. A private base stays private when it is exported and imported. A .brkb dropped on the dropzone is not imported.

Merge two bases

Ask the agent to merge one base into another. It previews the merge first: what carries over, what is renamed and what the result's privacy will be. Then it merges.

  • The destination wins every clash. An incoming page whose identifier already exists is renamed, and every link to it is rewritten.
  • Sources the destination already holds are skipped. The source base is left unchanged.
  • The merge is one commit, and any failure leaves the destination as it was.
  • A BioOKF base can merge into an OKF base. An OKF base cannot merge into a BioOKF base.
  • The result takes the more sensitive privacy of the two.

Ingest, query and lint

Three operations run on a base. When one needs a model, it runs as a subagent with a limit on steps and time: 60 steps and 15 minutes to ingest a source, and 30 steps and five minutes to answer a query or repair what a lint found.

OperationWhat it does
IngestDigests one source into linked pages, as one commit. Run it with Digest staged sources, from a chat, or with knowledge ingest.
QuerySearches the base and writes an answer that cites its pages. knowledge query --save also files the answer as a page.
LintReads every page and reports orphans, contradictions, missing pages, stale sources and anything that breaks the format's rules. In a BioOKF base that includes the vocabulary, the evidence on each link, and sources that are retracted or too weak for the claims on them. Check for problems and a chat only report; knowledge lint --fix lets the agent repair what it finds.

Soul

Soul (id soul) ships with Biorouter and starts empty. It collects lasting facts about you: how you approach research questions, the tools and commands you use, and the name, role and preferences you mention.

A schedule named Daily Meditation keeps it current. Every day at 3:00 AM, while Biorouter's background service is running, it runs the Meditation workflow, which uses the update-soul skill to read up to three recent chats and add what matters. It skips scheduled runs and small talk, and makes no change when there is nothing new. You can see and pause it in Scheduler.

The agent cannot delete Soul, and if you delete it Biorouter creates it again. Settings → App → Reset → Knowledge & memory deletes every base, creates an empty Soul and clears saved memory.

Private and public bases

A new base is public. It becomes private the first time a private chat writes to it, and it stays private until you make it public. A private base shows a padlock and the word Private beside its name. A public model that tries to read it is refused, and the refusal names the base.

The control sits on the Sources side. On a private base, hovering its badge shows “Private. Biorouter only lets a private model read or write this knowledge base.” Make private takes effect at once. Make public asks you to type the base's id first, because every model, public ones included, will then be able to read everything a private chat wrote into it. See Private and public.

Command line

biorouter knowledge list
biorouter knowledge create ms-genetics --name "MS genetics"
biorouter knowledge active --set ms-genetics
biorouter knowledge ingest --file ./paper.pdf
biorouter knowledge query "What predicts relapse?" --save
biorouter knowledge lint

Once active --set has made a base the primary, commands without --kb use it. kb is a short name for knowledge. Every flag is in the command line reference.
