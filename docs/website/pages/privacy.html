Private and public

Every chat is private or public. Once a chat has used a private model or private data, Biorouter keeps it away from models hosted outside your institution.

What is private

A provider is private only when Biorouter can tell where inference runs. Ollama or Llama Server pointed at another machine is public. Azure OpenAI and Amazon Bedrock on the Public tab stay public even when they point at a UCSF address; only the Versa providers are treated as UCSF's. Models and providers lists every provider by tab.

A private chat, model, extension or knowledge base shows a padlock and the word Private. Public ones show the word Public.

How a chat becomes private

A chat becomes private the first time either of these happens:

  1. A turn runs on a private model You send a message while Llama Server, Ollama or a Versa model is selected.
  2. A private data extension answers CDWAgent or UCSFOMOPAgent returns a result to one of the chat's tool calls.

It then stays private. The mark survives restarts and travels with the chat into diverged chats, imports, scheduled runs and subagents. Only you can remove it; see Make a chat public.

When you pick a private model for a public chat you have already sent a message in, Switch models says so before it applies: “After your next message this chat becomes private. Public models can't be used in it again unless you make it public from History.”

What Biorouter refuses

  • A private chat cannot switch to a public model. In Switch models each public model reads “Unavailable: this is a private chat, so only private models may run in it. Make it public from History to use this one.” The command line and other chats get the same refusal, and it names the provider. To use a public model, start a new chat.
  • A public model cannot read a private chat, through chat recall or through the tools that read other conversations.
  • A public model cannot read a private knowledge base. The refusal names the base.
  • A public model cannot use a private extension, and one cannot be turned on in a chat that runs a public model.
  • A subagent never crosses the line. See the table below.
  • A private chat writing into a public one asks you first. Before the agent in a private chat sends a message to a public chat or changes its tools, Biorouter shows you what it will send. It asks once for each pair of chats.

PublicPublicRuns. The subagent is public.
PublicPrivateRefused.
PrivatePrivateRuns. The subagent is private.
PrivatePublicRefused. The task a private chat writes is private too.

A public subagent is started without the parent's private extensions, and the parent is told what was left out. If a spawn is refused, retrying will not help: switch the parent chat, or start a new chat on the model you want.

Institutions

Private is about how sensitive the data is. A second check asks whose agreements cover it, because compliance approved at one institution does not cover another institution's data.

Llama Server, Ollama on this computerLocalEvery private extension. Nothing leaves the computer, so no agreement is needed.
Versa API Azure, Versa API BedrockUCSFPrivate extensions that allow UCSF, which today are CDWAgent and UCSFOMOPAgent.
Public modelsNoneNo private extension.

By default, when a model from one institution reaches an extension that belongs to another, the call is refused before anything is sent. The refusal opens with “Cross-institutional data flow” and names both institutions, and a button, Approve this flow for followed by the extension's name, appears under it. Only you can press it; an agent cannot. “Approving records your acceptance for this chat, this extension and this model's institution only.”

Approving is not a compliance decision. Biorouter cannot know whether a BAA, DUA or IRB approval covers the flow. Your compliance office answers that.

Knowledge bases

A knowledge base takes the tier of the most sensitive chat that has written to it. Merging two bases gives the more sensitive tier of the two.

To change a base's tier, open it in the Knowledge view. Make private takes one click. Make public asks you to type the base's ID and tells you how many pages and raw sources every model will then be able to read, including anything a private chat wrote. Content that has already been read cannot be recalled.

Make a chat public

  1. Open Chat history Choose See all under Recents, or press Cmd+2 (Ctrl+2 on Windows and Linux).
  2. Open the chat's menu Choose More actions (the three dots) on the chat's row, then Make this chat public. A chat opened from History also has a Make public button.
  3. Confirm What you are asked for depends on why the chat is private.
  • A chat Biorouter saw run a turn on a private model needs one click, then gives you five seconds to undo.
  • Any other private chat (it reached private data, was imported, came from a private parent, or was marked from the model it last used when privacy tiers arrived) asks you to type the last six characters of the chat's ID, then to pass your computer's own password prompt.

The contents are not changed, and the change cannot be undone once it lands. It is written to a record on your computer. An agent can ask you to do this but cannot do it. From a terminal:

biorouter session declassify SESSION_ID

Turning the protection off

Settings → App → Privacy has one switch, Privacy tiers, which is on by default. Turning it off asks you to type DISABLE PRIVACY TIERS, choose Turn off privacy tiers, then pass your computer's own password prompt. Turning it back on takes one click.

While it is off, nothing separates private chats, extensions and knowledge bases from public models, and a chat that uses a private model or private data while it is off is not marked private. Turning it back on protects what was already marked, but it cannot mark what happened in between.

The switch is kept in its own file beside config.yaml, not in it. An agent with a shell could still edit that file, which Biorouter cannot prevent, so it announces the off state instead: a note reading “Privacy tiers are off.” sits above every message box until you turn it back on. If the file was changed outside the app, the note says so.

What this does not protect

These rules govern what the agent can reach through Biorouter's own chats, knowledge bases and extensions. They prevent mistakes; they do not stop a determined person or an agent following injected instructions.

  • Files are not isolated. A public chat with a shell can read ordinary files on this computer, including files a private chat wrote and Biorouter's own chat store and knowledge base folders. The rules above cover what the agent reaches through Biorouter's tools, not through the shell.
  • The desktop is not isolated. Once you approve Biorouter Copilot for a request, the model receives screenshots and the text of other open apps. Close clinical windows first.

Every model that is not private carries this line, on the model chip, above the API providers on the Public tab, and in biorouter configure, whether or not privacy tiers are on:

“Not HIPAA-compliant, not on-premise, not local. This model can read files on this computer. Biorouter will not hand it another chat's transcript or a knowledge base marked private.”

For patient data, use a local model or an institutional one, and check with your institution before you start.
