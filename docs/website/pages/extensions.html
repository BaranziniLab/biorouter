Extensions and skills

Extensions give the agent tools for a clinical database, a knowledge graph, Word and Excel files or a website; skills give it written methods for doing one kind of task the same way every time. Both install from BAAM, the Biorouter AI Agent Marketplace.

What an extension is

An extension is a server that speaks the Model Context Protocol (MCP), an open standard. It offers tools the agent can call, and it can also offer resources to read and prompts to start from. Any MCP server that runs as a command on this computer, or over streamable HTTP, can be added. The older SSE transport is not supported.

Before it starts an extension through npx or uvx, Biorouter looks the package up in the OSV database of known malicious packages and refuses to start one that is listed.

These ship with Biorouter, so there is nothing to install. Defaults are those of biorouter v{{LATEST_VERSION}}; Crew arrives in the next release. Turn extensions on and off says where each one is switched.

Add an extension

From BAAM

  1. Open the marketplace Choose Extensions in the sidebar, then Browse extensions.
  2. Choose Add Biorouter downloads the extension and shows its name, publisher, version, privacy tier and what it contains. Nothing is installed yet.
  3. Enter any credentials, then install If the extension needs a key, passcode or login, the next step asks for it. Values it marks as secret are kept with your model keys; see Security. Choose Install extension to finish.

Never paste a credential into a chat. A credential typed there is not used to set anything up, and every model that reads the chat would see it.

You can also download a .brxt file from BAAM and drop it on Extensions → Add extension. In a terminal, the first command below installs one and asks for its credentials, hiding what you type for any value marked secret. The second asks for them again later.

biorouter extension install \
  ./cdwagent.brxt

biorouter extension configure cdwagent

The agent can install one for you. When a task needs a tool you do not have, the Extension Manager finds it on BAAM and asks you to approve that exact package before anything downloads. A chat on a public model cannot install a private extension this way.

A custom extension

Choose Extensions → Add custom extension and pick a type.

  • Standard IO (STDIO) is a program Biorouter starts on this computer, usually an MCP server run with npx or uvx. Enter the command with its arguments, and any environment variables it needs.
  • Streamable HTTP is a server that already runs somewhere else. Enter its endpoint URL, and any request headers.

An extension you add by hand, and any extension that is not on BAAM, is Public: any model can call it, including one hosted outside your institution.

For a STDIO extension, the app stores the value of each environment variable with your other credentials and writes only its name to config.yaml. In a terminal, biorouter configure and then Add Extension does the same. To try a server for one terminal session only:

biorouter session \
  --with-extension "uvx mcp-server-git"

biorouter session \
  --with-streamable-http-extension \
  https://mcp.example.org/mcp

In ~/.config/biorouter/config.yaml the two kinds look like this:

extensions:
  git:
    name: git
    description: My analysis code
    type: stdio
    cmd: uvx
    args:
      - mcp-server-git
      - --repository
      - /Users/me/analysis
    enabled: true
  lab-server:
    name: lab-server
    description: Our lab's MCP server
    type: streamable_http
    uri: https://mcp.example.org/mcp
    enabled: true

Skills

A skill is a folder holding a SKILL.md file: a short header with a name and a description, then plain instructions. It adds a method rather than a tool, such as a quality control checklist, a lab's plotting style or the steps for using an API. The folder can also hold scripts and templates the agent reads when it uses the skill.

---
name: rnaseq-qc
description: RNA-seq quality checks.
---

1. Drop samples under 10M mapped reads.
2. Plot a PCA and flag outliers.
3. Report what was dropped and why.

The agent reads each skill's description and loads the whole skill when a request matches it. To pick one yourself, type /skill: in the composer and choose it from the list. A skill is known by the name in its header, not by its folder's name.

Install a skill

  • From BAAM. Choose Skills in the sidebar, then Browse skills. Tick the ones you want and choose the install button, which shows the count, such as Install 3 skills. BAAM publishes more than 120 skills in three groups: core, developer and biomedical.
  • From a repository or a .zip. Choose Skills → Add skill. Paste a repository URL and choose Look up, or drop a .zip.
  • Write your own. Choose Skills → Add custom skill, fill in the SKILL.md it opens, and save. It goes in Biorouter's skills folder.
  • From a terminal. Run biorouter skill install with a repository URL or the path to a .zip.

The agent can install skills from BAAM or a URL as well. Each install or removal waits for you to approve it in the app; a reply in the chat cannot approve it.

Packages

A repository or a .zip can hold several skills that belong together. Biorouter reads the package's manifest when it has one and installs the skills as one package: a single row in every list, updated and removed as one. A package installs completely or not at all, and downloads come only over HTTPS from GitHub or biorouter.ucsf.edu.

When a .zip holds loose skills and no manifest, Biorouter asks whether to install them as one bundle or separately. In a terminal, answer with a flag:

  • --as bundle installs them as one package.
  • --as individual installs each skill on its own.

Turn skills on and off

The skills button under the text box, Manage skills, turns a skill or a whole package on or off for this chat only. The switches on the Skills page, and biorouter skill enable or disable in a terminal, set the default for every chat. A choice made in a chat wins over the default.

A few skills ship with Biorouter and are called Contexts: Word, PowerPoint, Excel and PDF documents, Knowledge, and a few about Biorouter itself. Turn them on or off in Settings → Chat → Contexts. They cannot be deleted, and the office ones load only for a matching task.

Where skills live

Biorouter reads skills from these folders, in this order. When two skills share a name, the one from the folder lower in the list wins.

  1. ~/.claude/skills/ holds skills shared with Claude Code.
  2. ~/.config/agents/skills/ holds skills shared with other AI agents.
  3. ~/.config/biorouter/skills/ holds the skills you install or write in Biorouter.
  4. ~/.config/biorouter/extensions/ holds the skills that come inside an installed extension, in its skills folder.
  5. .claude/skills/, .biorouter/skills/ and .agents/skills/ hold a project's own skills, in the folder where you run biorouter.

Skills are plain text. A lab can share a skills folder to keep its analyses consistent without sharing any data.
