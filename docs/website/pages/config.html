Configuration

Biorouter keeps its settings in one YAML file that the app and the command line share. This page lists the files Biorouter writes, the environment variables it reads, and which source wins.

The settings file

~/.config/biorouter/config.yaml holds the provider and model, the permission mode, turn limits, the extensions under the extensions key, and the other general settings. The app writes it when you change Settings, biorouter configure writes it from a terminal, and you can edit it by hand.

BIOROUTER_PROVIDER: llamacpp
BIOROUTER_MODEL: gemma4
BIOROUTER_MODE: smart_approve
BIOROUTER_MAX_TURNS: 100

Credentials are kept elsewhere; see Security. biorouter info -v prints the values stored in config.yaml.

Where files live

The paths below are for macOS and Linux. On Windows, ~/.config/biorouter/ is %APPDATA%\Block\biorouter\config\, and both ~/.local/share/biorouter/ and ~/.local/state/biorouter/ are %APPDATA%\Block\biorouter\data\. biorouter info prints the paths on your computer.

WhatPath
Settings~/.config/biorouter/config.yaml
Tool rules~/.config/biorouter/permission.yaml: always allow, ask or never allow, for single tools
Secrets~/.config/biorouter/secrets.yaml, only without a credential store
Privacy switch~/.config/biorouter/privacy-tiers.json: whether private and public protection is on
Workflows~/.config/biorouter/workflows/
Skills~/.config/biorouter/skills/

Global memories~/.config/biorouter/memory/
Built apps~/.config/biorouter/agent_drafter/
Chats~/.local/share/biorouter/sessions/sessions.db
Schedules~/.local/share/biorouter/schedule.json, with a copy of each scheduled workflow in scheduled_workflows/ beside it
Logs~/.local/state/biorouter/logs/

An administrator's policy file sits outside your profile; see Managed policy. BIOROUTER_PATH_ROOT moves everything above under one folder, in config/, data/ and state/.

Which setting wins

When the same setting comes from several places, the first of these wins:

  1. Managed policy, for the tool permissions and hooks it names.
  2. Environment variables, for the program that starts with them.
  3. config.yaml.
  4. Defaults.

For example, BIOROUTER_MODE=chat biorouter starts a terminal chat in Chat only mode and leaves the file alone. Most settings in config.yaml, such as those in the first table under Environment variables, can also be set as a variable of the same name. The variables in the second table work only from the environment.

When a change takes effect

  • config.yaml is checked each time a setting is read, so a change from the app, biorouter configure or an editor is seen at the next read, without a restart.
  • A chat takes its permission mode and the managed policy when its agent starts. Open a new chat to be sure a change applies.
  • Environment variables are read by each program when it starts. A command sees your shell's variables. When the desktop app starts its background service, it passes the environment it was opened from, so an app opened from the Dock or the Start menu does not see a variable set only in a terminal.
  • Secrets are read from the credential store once per process. A key saved in the app is used at once. A key changed by another program is read when Biorouter's background service next starts.
  • On macOS and Linux the background service keeps running after you quit the app, until the computer restarts. It keeps the environment and the secrets it started with, so a variable or a key changed by another program reaches it only once the service restarts. To restart it, run biorouter crew daemon stop; an open app starts a new service and reconnects. See The background service.

Environment variables

These settings can be written in config.yaml or set as a variable. The variable wins.

SettingWhat it does
BIOROUTER_PROVIDERThe provider, for example llamacpp. Names are on Models and providers.
BIOROUTER_MODELThe model, for example gemma4.
BIOROUTER_MODEThe permission mode: auto (the default), approve, smart_approve or chat. See Permission modes.
BIOROUTER_MAX_TURNSTurns the agent may take without you. Default 100.
BIOROUTER_AUTO_COMPACT_THRESHOLDThe share of the context window at which a chat is summarized. Default 0.8; 0 turns it off.

These work only as environment variables. Written in config.yaml, they have no effect.

VariableWhat it does
BIOROUTER_SUBAGENT_MAX_TURNSThe turn limit for a subagent. Default 25.
BIOROUTER_CONTEXT_LIMITOverrides the model's context window, in tokens. Useful for a model Biorouter does not know.
BIOROUTER_DISABLE_KEYRINGAny value keeps secrets in secrets.yaml instead of the credential store.
A key's own name, such as OPENAI_API_KEYSupplies that secret, ahead of the stored one.
BIOROUTER_SHELL_SANDBOXoff (the default), auto or strict. See Shell sandbox.
BIOROUTER_WORKFLOW_PATHMore folders to search for workflows, separated by : on macOS and Linux and by ; on Windows.
BIOROUTER_WORKFLOW_SCAN_WORKING_DIR1 also lists workflows found loose in the working folder. Off by default.
BIOROUTER_PORTThe port of the biorouterd that live session commands reach. Default 3000.
BIOROUTER_SERVER__SECRET_KEYThe API key those commands and that service share. See Sessions.
BIOROUTER_PATH_ROOTKeeps all settings, data and logs under one folder. Useful for tests and for separate setups.

The variables for browser access are on Browser access. Settings for single providers, such as OLLAMA_HOST, are on Models and providers.
