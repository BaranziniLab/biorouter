Built apps

Agent Drafter builds apps: a small web page with its own agent, which fills panels, draws charts and asks you questions while you use it.

What an app is

An app is a TypeScript front end (index.html and src/main.ts) with a manifest.json that sets its agent: instructions, model, extensions, skills, knowledge bases and what the app may do. Apps live in ~/.config/biorouter/agent_drafter/<id>/. Biorouter's background service serves each one at /apps/<id>/ and connects the page to its agent over a WebSocket.

Build one when a task needs a working surface rather than a transcript: a cohort reviewer, a variant workbench, a knowledge graph explorer, a dashboard for one lab. To see every app you have, open the sidebar's Components group and choose Built apps.

How the agent drives the app

Each app's agent gets a set of tools that act on the page. A call becomes a message on the app's socket and the page's SDK applies it. What you do in the page, such as answering a form or selecting a row, comes back over the same socket.

ToolWhat it does
ui_describeLists the page's regions, panels, declared actions and signals, and state. The agent calls it first.
ui_panel, ui_renderOpen a panel, or render widgets (cards, tables, stats, forms, Markdown) into a target.
ui_patchChange rendered widgets in place by id, keeping scroll position and typed input.
ui_chart, ui_graph, ui_figureDraw a chart, a network graph, or an Auto Visualiser figure such as a volcano plot or a survival curve.
ui_htmlRender HTML that Biorouter has cleaned of scripts and forms. Off unless the app allows it.
ui_highlight, ui_notify, ui_suggestPoint at a region, show a short message, or offer up to five next steps the user can choose or ignore.
ui_theme, ui_layoutSwitch the theme pack, accent, light or dark mode and density, or rearrange the layout.
ui_state, ui_patch_stateRead and change the shared state the page is bound to.
ui_askShow a form and wait for the answer. See Questions that wait.
ui_subscribeListen to signals the app declares, such as a row being selected.
app_call, emit_resultCall an action the app registered, or return a structured result the app is waiting for.
consultAsk one of the app's worker profiles a question that stands on its own. Works only when the app declares worker profiles; otherwise it says there are none.

Regions

An app marks the places the agent may write with a region attribute:

<section data-br-region="results">
</section>

The agent finds regions with ui_describe and writes to @region:results. It can also target @panel:ID, @main, @chat or a CSS selector such as #out. Panels need no region: every app has a dock for them. Up to 12 panels stay open by default, and the oldest closes when a new one opens.

Questions that wait

ui_ask shows a form in the page and holds the tool call until you submit it. The answers come back as the tool's result, so the agent can act on them in the same turn. Many apps have no chat box, so the agent asks this way rather than in prose.

A form holds up to 24 fields and waits up to 300 seconds by default. If the page closes or reconnects, the waiting question is released. Unlike ui_ask, ui_suggest never makes the turn wait.

Archetypes

A new app starts from a working archetype rather than a blank page. When none is named, one is picked from the app's title and description, and dashboard is the fallback. Each starter runs as it is and passes the build checks; all but chat declare their own actions and signals.

ArchetypeShape
explorerA network graph the agent draws, with an inspector and search.
dashboardA grid of key numbers bound to state, with a refresh action.
workbenchA table, row selection and a detail pane.
wizardA form in stages that saves as it goes, then submits.
canvasA drawing surface with actions the agent calls.
chatA plain conversation panel, picked only when the description asks for a chat or an assistant.

An app starts with Biorouter's look. Six theme packs are available: biorouter, clinical, lab-notebook, terminal, journal and midnight.

Build and export an app

  1. Ask for it In a chat, describe the app, for example “Use Agent Drafter to build a dashboard app for this cohort.” Agent Drafter is on by default.
  2. Let it build The agent creates the app from an archetype, edits its source, sets its model and tools, then builds it. build_app bundles src/main.ts and runs the app's checks; an error must be fixed before the app launches or exports.
  3. Open it A preview card appears in the chat; choose it to open the app in the side panel. The agent can also open it in your browser.

In Built apps, each row can Launch in browser, open the chat where the app was built, Export to a folder or delete the app. The card in a chat has no delete control. Delete an app here, or ask the agent to.

Exporting

Export to a folder offers two modes:

  • Launcher (app + scripts) writes the app and its launch scripts. It uses the knowledge bases, skills, extensions and models already on the computer that runs it.
  • Full (bundle server-side content) also packs the app's knowledge base (as a .brkb file) and the skills you tick, and optionally biorouterd itself. BAAM extensions you tick are listed in export.json, at the top of the folder, for the recipient to install. On the first run the launcher lists the skills and knowledge base and asks first. If you agree, it installs the skills and copies the knowledge base to ~/.config/biorouter/knowledge-imports/, for you to bring in with Import from .brkb in Knowledge.

The folder runs without a build step or Node.js. On macOS open run.command, on Linux run bash run.sh, and on Windows open run.bat. The launcher uses the biorouterd bundled in a Full export, or the one Biorouter installed on the computer. If there is none, it stops and says so; install Biorouter, or set BIOROUTERD_BIN to its path. It starts biorouterd in the background when it needs to and opens the app in the browser. An export carries no API keys, so the app uses the models configured by whoever runs it. The app's vault is never exported.

Security model

Biorouter treats an app's page as untrusted.

  • The socket. Each app has its own socket token, held in memory for one run of the background service and never written to disk. The socket accepts only the app page's own origin.
  • What the page sends. Action arguments, signals and widget submissions reach the agent wrapped in <app-data>, which the agent is told to treat as data, not instructions.
  • What the agent writes. State bindings set text and a short list of attributes, never code. ui_html is off unless the app allows it, and Biorouter cleans the HTML even then.
  • Capabilities. Control of the page is on by default, since it reaches only the app's own page. Files, data sources, compute and the vault are off until the manifest grants them. A signal that starts a turn by itself is off, and only you can turn it on; the agent cannot.
  • Knowledge. An app reads only the knowledge bases its manifest names, and writes only where it is granted write access.
  • Sensitive data. An app with an OMOP or CDW source, or a knowledge base it can write, may not send work to a public model. A model route or a worker profile that names one is refused.

An app's agent is a chat like any other, so the rules in Private and public apply to it.

Command line

biorouter apps list
biorouter apps open cohort-explorer
biorouter apps serve cohort-explorer

list prints every app (--json for scripts). open and serve use the background service on BIOROUTER_PORT (3000 by default) and start one if none is running. open opens the app in your browser; serve prints its address, and when it started the service it stays in the foreground and stops it when you press Ctrl+C. Apps always open in a browser, not in the terminal.
