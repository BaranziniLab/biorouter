Crew

Crew is where a lab works together in the Biorouter desktop app: channels, shared files, and agent tasks the whole channel can see. One member, the host, runs the workspace on a shared Linux server.

The examples use the workspace chen-lab on the server lab.example.edu, hosted by Alice Chen (@alice), and the member Bob Lee (@bob). A word in braces, such as {team}, is a name Crew fills in. Every dialog, message and command is in the Crew manual on GitHub.

This page describes Crew after v1.93.0, with automatic setup, open workspaces, deletion, agents that work on the server and @agent. For v1.93.0 itself, read the v1.93.0 Crew manual.

What Crew is

  • Open it from Crew in the sidebar, below New chat.
  • A workspace holds teams, and a team holds channels. You see only the channels you are in. There are no direct messages.
  • A new workspace is open: every member can invite people, let them in and manage teams and channels, and a person who joins is added to all of them. The host can make it managed, so that a team's creator and a channel's owner manage them and only the host invites. Only the host removes people from the workspace, changes its privacy or deletes it.
  • Privacy is Private or Public. It decides which AI models may read the workspace, not which people see it. Each channel is labeled "Restricted" or "Public-safe". Only a local model or one approved for the workspace's institution may read a Restricted channel.
  • The desktop app and the biorouter crew commands share one background service on your computer, so both show the same workspaces.

What you need

  • The desktop app. Tested on macOS. Crew does not work in a web browser opened with biorouter serve, which shows "Crew needs the Biorouter desktop app" in its place.
  • A server account. Your own login on the lab's Linux server, with an SSH key, a password or a verification code. Your IT team provides it.
  • Crew on the server. Its server program, biorouter-crew, in ~/.local/bin of every account that connects. When you join or host, Biorouter installs it in your own account, without administrator rights.
  • A verified server. The server's SSH host key in your known hosts file. Crew never accepts a new server by itself, so check the fingerprint with IT once.
  • An invitation. The host sends it. It expires after 24 hours.

The background service

On macOS and Linux, Biorouter starts the background service and connects to it automatically. You do not choose or type a daemon approval secret. Quitting the app leaves the service running, so Crew stays connected. Opening the app again uses the same service.

  • After your computer restarts, opening Biorouter or running a biorouter crew command starts the service again.
  • After an update, the app replaces the older service when you open it. This can interrupt a task or transfer, so check their status afterward.
  • On Windows, quitting the app stops the service, and the biorouter crew commands do not work.

A Crew vault has its own passphrase. Setting one up or unlocking it still asks for that passphrase; see Use an encrypted vault.

Join a workspace

Send the host your exact username on the server. The host sends back an invitation message that ends with a line starting brcrew1:. It holds no secret.

  1. Open the Join dialog In Crew, choose Join a workspace. If you already have a workspace, choose Add a workspace and then Join a workspace… in the workspace menu.
  2. Paste the invitation Paste the whole message into Invitation from your host. If the summary names the wrong workspace or host, choose Cancel.
  3. Check your username The name in Your username on lab.example.edu is your server login, not your email address.
  4. Choose what your agent may do Check Your agent on lab.example.edu. It starts at As me on the server, which lets your agent run commands as your account there. Choose In a folder or Off to give it less. See Agents on the server.
  5. Join Choose Join chen-lab. If Crew is not in your server account yet, Biorouter installs it there. If the server asks for a password or a code, type it in the Sign in window.
  6. Send your code Crew shows "Send Alice this code:" and your code. Choose Copy and send the code to the host.

When the host, or in an open workspace any member, enters your code, the workspace opens by itself. Until then the status row reads "Not joined yet". In an open workspace you are added to every team and channel. For a second computer, ask the host to invite you again with Add another device for @bob turned on.

Your code is not the fingerprint. The Join dialog can also show the workspace fingerprint. Never send it. To check an invitation, ask the host to read the fingerprint from their workspace menu. If the two differ, do not join.

Host a workspace

You need a login on the server, the server in your known hosts file, and your institution's short ID, such as ucsf.

  1. Open the Host dialog In Crew, choose Host a new workspace. If you already have a workspace, choose Add a workspace and then Host a new workspace… in the workspace menu.
  2. Name it Type a Workspace name. Anyone who can sign in to the server can see it, so keep patient and sample IDs out of it.
  3. Give your login Type Your server login, such as alice@lab.example.edu. Keep Private, check the institution and Your agent on lab.example.edu, as when you join, and choose Continue.
  4. Set up and start Crew Choose Set up and start Crew. Biorouter installs Crew in your server account and starts the workspace. If the server asks for a password or a code, type it in the Sign in window. If setup stops because other accounts can change a folder above the workspace, choose Fix it for me. If setup cannot reach the server, open Run it yourself in a terminal, run the commands it shows, and paste their output into Paste what it printed.
  5. Create it Choose Create workspace. This computer becomes the workspace's first admin device. Create also makes the workspace open and drafts its workspace context from the server. With Private, it marks the workspace with your institution, which cannot be changed later.
  6. Set the institution if asked If Create did not mark the workspace and Crew asks "Mark chen-lab as a UCSF workspace?", choose Mark as UCSF. Agents cannot work in the workspace until it is set.

From a terminal, one command does all of this:

biorouter crew host \
  --name chen-lab \
  --server alice@lab.example.edu \
  --institution ucsf

The "Get chen-lab ready" checklist lists what is left. Set your name before you invite anyone, because each invitation carries it.

Invite people and let them in

  1. Invite Choose Invite people to chen-lab… in the workspace menu. Type the person's server login in Username, such as bob, and choose Invite. In an open workspace, any member can invite.
  2. Send the invitation Choose Copy and send the message to the person, with the server's SSH fingerprint from IT if they have not used this server before.
  3. Let them in When the person sends their code, choose Let in… beside their name under "Waiting to join", paste the code, and choose Let Bob in.
  4. Add them to a team In an open workspace they are already in every team and channel, so choose Done. In a managed one, when their computer checks in, tick channels under Channels in {team} and choose Add to {team}. A person in no team sees no channels.

Approve only a code the person sent you. If Crew warns that a computer showed a different code, check the code with the person directly. To correct a mistyped code, choose Let in…, enter the right one, and choose Replace code.

After the server restarts, the host starts the workspace again, as Server setup says. More in Hosting a workspace.

Delete the workspace

In the workspace menu, choose People…, then the General tab of "chen-lab settings". Under "Danger zone", choose Delete workspace…, type the workspace's name, and choose Delete workspace. This deletes it for everyone and cannot be undone. Each member's connection bar then says "The host deleted chen-lab." with Remove from this computer…, which is all they can do.

Messages and files

  • Enter sends, and Shift+Enter starts a new line. Messages use Markdown.
  • If sending fails, your text stays in the box with the reason. Press Send again. An unchanged message is never posted twice.
  • Typing @bob mentions Bob. Bob sees the message marked for him and may get a notification.
  • Nobody can edit or delete a posted message. To search a channel, use biorouter crew search in a terminal.

Share a file

  1. Add the file Choose the paperclip, then Upload a file…, and pick the file. You can also drag a file onto the channel, or paste a copied file into the message box. For a dragged or pasted file, Crew asks, for example, 'Share "counts.csv" (55 KB) to Crew?'. Check the full path it shows, and choose Share.
  2. Wait for the upload Wait until the line "Press Send to share it." appears.
  3. Send it Press Send. The file appears in the channel as a card with its name and size.

The file leaves your computer as soon as you confirm it. A finished upload cannot be deleted, even if you remove it from your message. The × on a file still uploading is Cancel upload. If you cancel, the part already sent stays on the server for up to a day.

Crew refuses folders and credential files, such as .env or id_rsa. For a large file already on the server, choose the paperclip, then Share a server path…, and type the full path. Crew shares only the path, and others open the file only if their own server account may read it. More in Messages and files.

Privacy and institutions

SettingWho changes itValues
Your connectionYou"Private" or "Public"
WorkspaceThe host"Private for everyone" or "Allows Public"

Your privacy is Public only when your connection is Public and the workspace allows Public. A new workspace starts "Private for everyone", and only the host can allow Public. The host sets the workspace's institution once, and your connection's institution must match it.

What an agent reads is protected when your privacy is Private, when it reads a "Restricted" channel or anything marked Restricted, when it uses your remote work folder, or when its chat already holds Restricted material. Restricted content stays Restricted after the host allows Public. The background service on your computer and Crew on the server apply these rules even when Privacy tiers is off in Biorouter's settings.

What other people can see

  • Members of a channel see your display name, your username, and your messages, files and agent posts there.
  • Everyone in the workspace sees whether you are online.
  • Members never see your privacy, your institution, your devices or your connected chats.
  • The host's server account and the server's administrators can read everything the workspace stores, Restricted messages included.
  • Anyone who can sign in to the server can see the workspace's name, and who is connected to it, in the server's process list.

Agents in a channel

An agent can work in a channel in two ways. Both run on your computer with your model, post as your agent where everyone in the channel sees it, and have access for one hour at most.

DetailA taskA chat connected with /crew
KindOne task, from Ask my agent or @agent. The agent posts its result and its access ends.An ordinary Biorouter chat that you keep talking to.
ReadsIts channel and its files, and up to 16 more channels under Also read. In an open workspace, every channel you are in.Its channels and their files, up to 20 including its own
PostsYour task, then its resultIn its one channel
Stop itChoose Stop on its rowChoose Revoke access in the chat

Access ends for every agent in the workspace when someone is removed from a channel or the workspace, or, in a managed workspace, added to a team or channel, when a channel is archived or offered to a new owner, and when the workspace's privacy or institution changes. Deleting a channel or a team ends the access of agents that read it. A change to your own connection's privacy, settings or institution ends your own chats' access. Renaming a team, a channel or the workspace does not.

Ask my agent

  1. Open the pane In the channel that should get the result, choose Ask my agent, the robot icon left of Send.
  2. Write the task Type it in Task. Enter starts a new line.
  3. Check the model Model starts on your model for Crew tasks, which Settings → Models → Crew tasks sets. Choose Change for another. To let the agent read other channels, open Advanced and tick them under Also read.
  4. Start it Choose Start my agent and allow posting here. The task's row in the channel shows its status, such as "Working…".

Crew posts your whole task in the channel, so do not paste data you would not post there yourself. "Waiting for your approval" means the agent needs your answer: choose Review. The result ends with a line from Crew that names the shared files the task read, or says it read none. Trust that line over the agent's words.

You can also start a task from the message box: type @agent, /agent or /task at the start of a message, then the task, and press Enter. The line under the text says which model starts and what the task reads. As with Ask my agent, Crew posts the whole task in the channel.

Connect a chat with /crew

The chat needs at least one sent message, a model, no reply in progress, and no attachments in its message box.

  1. Type /crew Type /crew alone in the chat's message box and press Enter. Nothing is sent to the model.
  2. Check the pane Crew opens at the channel you last had open, with the Chat access pane. It names the channel, the workspace and the chat's model. For another channel, choose it in the Crew sidebar, then Review access. To let the chat read more channels, open Advanced and tick them under Also read.
  3. Allow Read what the pane says the chat will be able to do, then choose Allow. The pane shows "Connected." and the time access ends.
  4. Go back to the chat Choose Back to chat. The chat shows a "Crew · #methods" chip and Revoke access.

The chat can read its channels and their files, post in its one channel, and with a private model use the server as your connection allows. It cannot use other Biorouter tools, such as the shell or files on your computer, and these limits stay after its access ends. The first access fixes the chat's workspace, channel and model for good. To end access, choose Revoke access, then Revoke. Deleting a chat does not revoke its access.

Agents on the server

Each connection says what your agents may do on the lab server. Choose it when you join or host, or later in Connection settings… in the workspace menu. It applies to every task and connected chat through that connection, and only with a local model or one approved for the workspace's institution.

LevelWhat your agent may do
OffNothing on the server.
In a folderReads and writes one folder. With Let my agent run commands in this folder, it also runs commands there. They have no network, cannot start other programs, and need Linux 6.2 or newer on the server.
As me on the serverRuns commands as your own account, with your files, programs and network. Long work can run as a job that keeps running after the task ends, and the agent can copy files between the channel and the server.

A new connection starts at As me on the server. Your agent can then read and change anything your account can, and other people's messages and files can try to steer it, so use a private model you trust. If you host the workspace from that account, it can also read channels you are not in.

Before it works on the server, every member's agent reads the workspace context: a short page about the server, such as where data lives, which software is there and how jobs run. Crew drafts it from the server when the workspace is created. In an open workspace every member edits it on the Context tab of "chen-lab settings", and in a managed one only the host does. More in Agents and chat access.

Limits

A file can be up to 1 GiB, one computer runs at most four agent tasks at once, and a workspace keeps up to 16 MiB of state and 10 GiB of shared files. Workspace limits lists the rest.

Command line

The biorouter crew commands reach the same workspaces as the app, on macOS and Linux. Add --help after any command for its options.

  • setup installs Crew in your server account and connects. On a new connection it also gives agents As me on the server; add --agent-access folder or off for less. doctor --server LOGIN checks a server without changing anything. defaults set --provider PROVIDER --model MODEL sets the model Crew tasks start on, and connections set-access off, folder or full sets what agents may do on the server.
  • Workspace and credentials commands start the background service when needed and connect without a daemon approval secret. --no-start connects only to an existing service. daemon status checks the status without starting it.
  • Setting up or unlocking a Crew vault still asks for its passphrase. In a script, --passphrase-stdin reads that passphrase from the first line of standard input.
  • --approval-key-stdin remains accepted for older scripts: it reads and ignores the first line of standard input. It cannot be combined with --passphrase-stdin.
  • --connection NAME chooses a saved connection when you have more than one.
  • --output-format json prints JSON, errors included, with a code to match on. Exit status is 0 for success, 1 for a failure or refusal, and 2 for a wrong command line or a command that needed a terminal.
# Join a workspace
biorouter crew connections \
  join-invitation ./lab.txt
biorouter crew setup
biorouter crew join

# Post, then start an agent task
biorouter crew send methods \
  --text 'Plate reader data is in.'
biorouter crew ask methods \

privacy set-personal public and privacy set-workspace public ask you to type the workspace name first, as the desktop app does. In a script, add --confirm WORKSPACE. More in Command line.

When something goes wrong

If Crew says a feature needs a newer background service, quit and reopen Biorouter. On macOS and Linux it replaces the older service. For command-line use, run biorouter crew daemon stop, then your command again. An open app starts a new service and reconnects automatically.

If Crew says "Crew isn’t set up for your account on lab.example.edu", choose Set up Crew for my account, and Biorouter installs it.

The status row names your connection's state, such as Connected, Offline or Sign-in needed, and the main area or the connection bar says what to do next. After a network drop, Crew reconnects by itself for up to an hour, and it never sends a message twice. If the server's identity changed, do not connect. Copy the details for your IT team instead. Connections and troubleshooting lists every status and message.

Server setup for administrators

The host's copy of biorouter-crew keeps the workspace in files owned by the host's account and checks every request. Each member's Biorouter starts the same program in the member's own account over SSH, which passes requests to the host's copy through a Unix socket under /tmp. Crew needs no root, no system service, no open network port and no database.

  • Linux on x86_64 with glibc 2.31 or newer, and a valid /etc/machine-id owned by root.
  • A local disk for the workspace's state. NFS, CIFS and SMB are refused.
  • An ordinary account for the host, and each member's own account on the same machine.
  • Linux 6.2 or newer (Landlock ABI 3) for agents that run commands In a folder. On an older kernel, such as Ubuntu 22.04's original 5.15 kernel, they run commands only with As me on the server.

Biorouter installs biorouter-crew in ~/.local/bin of each account itself, over SSH, when that person joins or hosts. It sends its own copy, which ships with the desktop app and the biorouter-cli packages, and needs no administrator rights. biorouter crew doctor --server LOGIN checks a server first and changes nothing. Nothing starts the workspace when the server boots, so after every restart the host runs start again. Crew has no backup tool. SSH encryption alone does not make a deployment HIPAA compliant: your institution decides approval, retention and backup. Administration has the manual install, the full requirements and the upgrade steps.
