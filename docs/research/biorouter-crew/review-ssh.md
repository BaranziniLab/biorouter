## Secure SSH preflight implementation review — 2026-09-22

Independently reviewed `crates/biorouter/src/crew/ssh_policy.rs`, its authentication and bridge call sites, and `ssh-hop-policy.md`. This review was source-only: no builds, tests, SSH connections, or product edits. OpenSSH behavior was checked against upstream revision `ccc26c76cd47ca224ff5e4ef8b96007b65ff0b4e` and historical release sources, rather than inferred from URL parsing conventions.

### Findings resolved in the reviewed source

- **P1 — IPv6 spelling must survive policy inspection.** The initial URL-based parser compressed IPv6 addresses. That could inspect a different first-pass `Host`/`Match originalhost` identity from the actual implicit SSH child. The replacement `jump_authority` preserves the admitted host spelling and case, strips structural brackets only, and retains the user and port (`ssh_policy.rs:202-257`). This matches OpenSSH's preservation of the parsed jump host and initial configuration lookup. [OpenSSH jump construction and configuration passes](https://github.com/openssh/openssh-portable/blob/ccc26c76cd47ca224ff5e4ef8b96007b65ff0b4e/ssh.c#L1132), [host parsing](https://github.com/openssh/openssh-portable/blob/ccc26c76cd47ca224ff5e4ef8b96007b65ff0b4e/misc.c#L982)
- **P2 — Numeric IPv4 jumps must accept OpenSSH's diagnostic brackets.** OpenSSH can print `proxyjump [127.0.0.1]`; a general URL parser treats those brackets as IPv6 syntax and rejects the route. The replacement parser accepts bracketed IPv4 as well as IPv6, with source fixtures for each (`ssh_policy.rs:323-351`). [OpenSSH ProxyJump diagnostic output](https://github.com/openssh/openssh-portable/blob/ccc26c76cd47ca224ff5e4ef8b96007b65ff0b4e/readconf.c#L3944)
- **P2 — Older OpenSSH clients lack the `forkafterauthentication` dump field.** Requiring that field rejected otherwise valid older installations. The current code permits absence, rejects an affirmative reported value, and rejects Crew's separately constructed `-f` argument (`ssh_policy.rs:28-33,127-130`). The documentation now permits omission of the unsupported keyword. Historical clients implement backgrounding through `-f`. [OpenSSH 8.2 configuration source](https://github.com/openssh/openssh-portable/blob/V_8_2_P1/readconf.c), [OpenSSH 8.2 command-line handling](https://github.com/openssh/openssh-portable/blob/V_8_2_P1/ssh.c#L688)
- The negative-test fixture now places specific host settings before `Host *`, and the shell-syntax assertions now match the actual errors. Both earlier source-level test defects were corrected; these tests were not executed in this review.

### Current source assessment and remaining qualification

Within its deliberately restricted grammar, the implicit-child construction reproduces OpenSSH's optional `-l`, `-p`, remaining `-J`, inherited `-F`, and `-W` arguments. In particular, it preserves the remaining chain verbatim and does not assume final-host `-o` options propagate. The `-W` invocation participates in effective configuration: configured forwarding values still take precedence over its defaults. OpenSSH's diagnostic dump reports native ProxyJump separately from its generated ProxyCommand, so rejecting a separately reported custom ProxyCommand does not itself reject normal native jumps. [Implicit command construction](https://github.com/openssh/openssh-portable/blob/ccc26c76cd47ca224ff5e4ef8b96007b65ff0b4e/ssh.c#L1307), [stdio-forward defaults](https://github.com/openssh/openssh-portable/blob/ccc26c76cd47ca224ff5e4ef8b96007b65ff0b4e/readconf.c#L2873)

Both authentication (`mod.rs:670`) and bridge startup (`transport.rs:73`) invoke preflight before returning/spawning their real SSH command. Required missing or unsafe scalar settings, cycles, excessive depth, failed `ssh -G`, invalid UTF-8, and excessive output fail closed. Source inspection confirms a 30-second bound on the complete inspection and a one-MiB output bound per child. Final app-owned multiplexing is retained; implicit jump hosts must reject inherited control sockets. These conclusions assume the documented trusted same-user/site-administrator configuration boundary; this review does not require a configuration sandbox or lossless reconstruction of `ssh -G` output.

**P3 — Windows path documentation clarified; resolved.** Independently reread `ssh-hop-policy.md:25` after correction. It now explicitly says inherited `-F` paths containing backslashes are rejected, including the no-space example `C:\crew\config`, and that native Windows configuration-path quoting and ProxyJump behavior remain unqualified. This accurately describes the admitted `shell_atom` grammar (`ssh_policy.rs:155-160`). Closing the documentation finding adds no runtime or Windows compatibility evidence.

No additional product defect was identified in this bounded reread. Runtime acceptance remains separate: the new test omitting the ForkAfterAuthentication configuration directive still receives that field from a modern client's dump, and therefore does not establish legacy absent-field behavior. A synthetic missing-field check or an actual older client is needed for that specific claim. Numeric IPv4, noncanonical IPv6 with differing `Match originalhost` policy, compound URI chains, time/output caps, real hop authentication, and Windows behavior also require their own recorded execution evidence.
