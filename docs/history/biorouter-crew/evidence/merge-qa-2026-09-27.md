# Crew merge QA evidence, 2026-09-27

> **What this is.** The record of the QA campaign that tested Crew after it merged into `main`: a static audit of the merged code, two live runs on disposable AWS fleets with synthetic data, three fix waves on branch `claude/crew-qa-fixes-2026-09-27`, and the final live re-check of the last wave. It lists every finding by severity, the commits that fixed it, each live verdict and what is still open.
> **Status:** Historical record, complete. The campaign ran from 2026-09-27 07:06Z to 2026-09-29 06:50Z. Its fixes are in PR #377. Each verdict holds for the build it names; later commits need their own runs.
> **Audience:** Maintainers deciding what Crew can claim after this campaign, reviewers of the security-sensitive commits, and whoever runs Crew's next QA.

Crew merged into `main` on 2026-09-27 as PR #366 (head `ead0498d6`). This campaign, named `crew-merge-qa-2026-09-27`, tested that merged build as real people would use it: lab members on Macs, a host on a shared Linux server, a member on a Debian 11 machine, a Slurm cluster behind a bastion, a password-only account and an adversary with an ordinary account. Every agent turn used the private Versa `versa_azure` / `gpt-5.5-2026-04-24` model. No local model was used as a test driver, and all data was synthetic.

**Identifiers used below.**

- `BROKER-n`, `DAEMON-n`, `RENDERER-n`, `CLI-n`, `DOCS-n`, `PROVIDERS-n` and `CROSSCUT-n` are the static audit's findings.
- Live findings from run 1 carry their lane's prefix: `SETUPHPC-Fn`, `SF-Fn` (setup-foreign), `Fn` (setup-chen), `SEC-n` (security), `DW-nn` (docs walk), `Mn` (messaging), `AG-Fn` (agents), `PROV-Fn` (providers), `R-n` (resilience) and `FILES-Fn`.
- `W2-*` items are the wave-2 triage of the run 1 findings. `T3-*` items are the wave-3 triage of run 2's findings.
- Severity: **P0** a security boundary broken or data lost; **P1** a core task broken, or a security weakness with a precondition; **P2** an inconsistency, copy, polish or documentation problem.
- A task is **unaided** when a person with only the app or the manual finished it, **friction** when they finished after a detour, and **failed** when they could not.

Raw evidence stays local under `/private/tmp/crew-qa-2026-09-27/` on the machine that ran the campaign and is not published: screenshots (`shots/`, `shots2/`), CLI logs, journals, receipts, mailboxes and the lane reports (`reports/`, `reports2/`). Finding data is in `findings/`. No secret value appears in this record or in the reports.

## What this establishes, and what it does not

- **No P0 in either live run.** No confidentiality boundary broke and no acknowledged data was lost. Every broker, daemon and institution boundary the adversary and the lanes tested held on the merged build and on both fixed builds.
- **Every finding was fixed.** The static audit's 59 items, the 117 new wave-2 items (plus the two static items deferred to wave 2) and the 85 wave-3 items each have at least one commit on the branch. [Fixes by wave](#fixes-by-wave) maps them.
- **The final live round passed on `341df2d06`:** 80 of 85 wave-3 items pass, 3 are partial, 1 could not be reproduced and 1 could not be run. It found no P0 or P1 regression.
- **Not established:** Windows and Linux desktops, the packaged and notarized app (every run used a frozen development build), native macOS sheets (Save, Open and the share confirmation), the Azure content filter's retry notice, and the reattach prompt after a daemon restart on a packaged build. [What is still open](#what-is-still-open) lists each gap.
- **Synthetic data only.** Nothing here establishes institutional deployment or HIPAA compliance.

### After the final round: hosted CI

The first hosted CI run on the PR's head failed on the three test jobs, for four reasons the local and live runs could not see. Two commits after `341df2d06` fixed them. Neither was re-checked on the fleet.

- `92094da45` (product): the exported app launcher checked its one-time token with the glob `*[!0-9a-f]*`. macOS's `/bin/bash` 3.2 reads that range by the locale's collation under a UTF-8 locale and accepted an upper-case token. The digits and letters are now listed. The same commit runs a launcher test from a file instead of `bash -c`, because Git Bash on Windows misparsed the program text on its command line.
- `5443d717b` (tests only): two Crew tests asserted "no typed refusal at all" past the privacy guards, which a Linux runner with no keyring service answers with a typed `crew_credential_store_unavailable`; and the Claude Code and Codex fake CLIs are now written by a child process, so a concurrent fork elsewhere in the test binary cannot make their `exec` fail with `ETXTBSY`.

## Security results

**Boundaries that held in run 1** (security lane, on throwaway workspaces the adversary hosted, and on her own Mac daemon):

- The broker refused every real method without a device signature, accepted a signature only for the connecting kernel UID, and closed oversize frames.
- A member was refused every host-only method (`policy.set`, `enrollment.invite`, `enrollment.revoke`, `workspace.rename`).
- Holding a daemon's secret did not grant Crew: every `/crew/*` route refused a caller without the proof that a person acted, so a public chat's shell could not read a private workspace, post, grant, approve a join or download.
- SSH option injection was refused, `ProxyCommand` was refused at preflight, and identity files had to be absolute.
- Device codes and invitations could not be guessed or replayed to any effect: a claim needs the joiner's private key, the invited UID and an unchanged username and generation, and enrollment tokens are single use with a 1 hour lifetime.
- A malicious host could not choose where a download was written, and adversarial message content (HTML, `javascript:` links, a 6,000-character line) caused no script execution and no crash in the victim's app.

**What the run 1 security lane broke** (all fixed): one member could freeze all writes by filling the shared state (SEC-1, BROKER-1), kill file sharing by exhausting the attachment quota (SEC-2, BROKER-4), bloat the unpaged snapshot (SEC-3, BROKER-2) or squat the host's `/tmp` runtime path so the workspace could not start (SEC-4, BROKER-3); decoy directories defeated name uniqueness (SEC-5); the daemon's loopback listener was undocumented (SEC-6), and with SETUPHPC-F3 it let another local account fetch an Agent Drafter app's socket token (W2-HRD-1); and bidi and control characters rendered verbatim (SEC-9).

**Runs 2 and final:**

- On the login node, under SELinux Enforcing on an NFS home, the adversary could not list the runtime folder, rename the socket, read any Crew state or the daemon's environment, and was refused every method before sign-in beyond invitation-level data; decoy runtime directories did not disturb the running broker.
- Every `/apps/*` path on another account's daemon now answers one indistinguishable 401. The listener itself and its secretless `/status` remain, by design and documented.
- The institution gate refused a UCSF model on the `stanford-synthetic` workspace in the app, the CLI and the daemon, before any model call. A Crew chat's model could not be switched, and `POST /agent/update_provider` answered 409.
- Revocation reached the broker exactly once per Stop, re-granting revoked the old run, removing a connection revoked live runs and deleted all three credential files, and an offline revoke was confirmed about 8 s after the connection returned.
- Export, workflow creation and "Make this chat public" were refused for a Crew chat with a sentence, and a separate CLI process refused a chat the daemon had granted.
- Files: credential-shaped files were refused with none of their bytes reaching the host, crafted traversal names could not escape the chosen folder, names with invisible, formatting or blank filler characters were refused before any transfer existed, and a download path through a symbolic link was refused in words.

## What is still open

- **The stopped-saving state reaches members late (T3-BE-13, T3-UI-18, P2).** A member who writes nothing and whose app idles away from Crew may not learn that the server stopped saving, and the app's bar changes only on a window focus event. The final round suggested refreshing a connection with a `hello` once another member's write is refused for storage, and re-reading the saved connections on the observation's own cadence.
- **`--expected-mode public` under a Private workspace (T3-BE-5, P2).** Accepted when the connection's own mode is Public. It fails safe, but a script that requires Public is not told that its post was private.
- **Not verified live:** T3-UI-22 and every other native macOS sheet; T3-SH-9's content-filter notice; the reattach prompt after a daemon restart on a packaged build (a harness limit: the development profile's one-time approval key on stdin cannot be read again); the Save sheet's default name for blank filler characters and middle truncation (T3-UI-21); the onboarding card path of the wrong-key check (T3-SH-3); the Versa Bedrock refusal wording (T3-SH-8, code only, no Bedrock key available).
- **Final-round observations, not yet triaged (all P2):**
  1. `grants list` still shows as Active a grant that ended when the person changed their own privacy setting, while `context` answers `crew_grant_ended` and `run --resume` refuses it.
  2. `run --shared-daemon --resume` of that chat prints the app's wording ("Grant access again from Crew.") rather than the CLI sentence.
  3. The `crew_grant_ended` JSON `error` names the channel by its ID where the text names it.
  4. SSH refusals put the text form's `Code:` and `Details:` lines inside the JSON `error` string.
  5. The host's own `files status` for an upload paused by a full disk says "Ask the host to free space".
  6. The member's broker-down copy says "connects by itself within a few minutes" where 13 to 16 s was measured (the manual says "within about a minute").
  7. **Configure Versa API Azure** opens with focus on **Remove**.
  8. Escape from **Switch models** opened from the composer leaves focus on the page.
  9. The configuration editor's **Done** discards a typed value that was not saved with its field's own Save button.
  10. `connect` prints "Status: Connected" for a saved connection that has not joined, where `status` says "Not joined yet".
- **Kept by design or decision:** the daemon's loopback listener and secretless `/status` (the desktop's liveness probe; `administration.md` and `privacy-and-security.md` describe what another account can see); the toast position, which the user decided; reply, quote, direct messages, mute and leave, which Crew does not have; one-click restart of a stopped broker from the app, which would need a new privileged route.
- **Leftovers the fix results name that no later wave closed:**
  - A link whose public-looking host resolves to a private address is still refused without saying why (RENDERER-3's residual; only the main process's DNS lookup can know).
  - The snapshot's team and channel member lists are bounded by the per-member caps (10 teams, 100 channels) times the number of members, not paged (BROKER-2's residual), and `channels list` and `teams list` do not say when a listing was cut short.
  - An Agent Drafter app's cookie is not scoped to a port, so on a shared host a page on another account's loopback server could have a system browser send it there; closing that needs HTTPS or a per-request proof. The cookie is also not rotated when it is redeemed. (W2-HRD-1's residuals, a weakness with a precondition.)
  - The secret guard does not cover the daemon key records under `<state>/apps-daemon/` or the one-time launch pages under `<state>/app-launch/` (defence in depth; both are 0600).
  - The new browser opener for app links was exercised on macOS only.
