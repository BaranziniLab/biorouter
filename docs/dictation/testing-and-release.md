# Dictation testing and release

> **What this is.** How local dictation is proved and shipped: the tests for each component and surface, the CI jobs that run them and the network each one may use, the release guards and packaging checks, the committed fixtures and their size budget, the accuracy gates on public recordings and synthetic speech, and the definition of every measurement. The manual checklist for every surface and the dated measurement log are in the [dictation test checklist](../releases/dictation-test-checklist.md).
> **Status:** Current: the record of local dictation as it was built on branch `feat/local-dictation`, PR-01 to PR-33 (PR-07 and PR-32 withdrawn), with every code pull request committed by 2026-11-10 and before the release that carries it. Design rationale and the measurements taken while building it are kept with their dates; "As built" notes say where the code differs from the design.
> **Audience:** developers who maintain each component's tests and CI jobs; the maintainer who cuts releases and runs the [dictation test checklist](../releases/dictation-test-checklist.md); reviewers who check that a change carries its own gates.

The [implementation plan](implementation-plan.md) decides what is built and in which order. This document decides how each piece is proved before it merges, before a release is published, and before version 1 is announced. Almost every test runs offline inside CI steps that exist today, with whisper.cpp's own empty test models and one committed speech clip. What CI cannot do (a real microphone, a macOS permission prompt, Safari, a person's terminal, a real proxy, a signed app on macOS 12) is in the [dictation test checklist](../releases/dictation-test-checklist.md), one section per surface. Accuracy is held by two tiers: a networked nightly job on public real speech, and a maintainer run on public recordings and synthetic speech, on Metal and on the CPU, before any release that changes the engine or a model pin. Biorouter records no real voices for evaluation (the owner's decision O-23, 2026-11-05), its tests and measurements use only PriMock57, the Fareez et al. 2022 interviews and synthetic voices (O-38), and no accuracy claim about the product ever goes into user documentation, release notes, the announcement or the interface (DD-95).

## Principles

1. **Offline by default.** Every new `tests/*.rs` binary runs in the offline step, which builds every integration target its exclusion table does not name, runs it with `CARGO_NET_OFFLINE=true` and the keyring disabled, and never passes `--ignored` [C `rust.yml`]. No dictation binary gets a line in that step's exclusion table. A test that needs a real speech model or the network is `#[ignore = "downloads a pinned speech model"]` inside the same binary, the pattern of [`llamacpp_integration.rs`](../../crates/biorouter/tests/llamacpp_integration.rs) [C]. The offline step compiles it and skips it; `dictation-accuracy.yml` or a maintainer runs it.
2. **Unique target names.** The offline step fails when two packages share an integration target name [C]. Every binary named here is unique across the workspace.
3. **Gates land with the change.** The guard, smoke line or CI step that proves a pull request lands in that pull request (rule 2 of the plan's delivery rules). No pull request job links the Linux or Windows release binaries: `cross-check` runs `cargo check`, which runs build scripts and so compiles the C and C++ in both cross images, but never links [C]. A pull request that touches the engine, its build or `vendor/whisper.cpp/` therefore dispatches `rust.yml` before merge and links the green run in its description; the dispatch also runs `cross-build-nightly` [C].
4. **Keyless cases in their own binaries.** The user action digest is a process global `OnceLock`, so a binary that installs it can never observe a keyless daemon again. Every keyless case lives in a `*_no_user_key.rs` binary, as [`turn_control_no_user_key.rs`](../../crates/biorouter-server/tests/turn_control_no_user_key.rs) does today [C].
5. **Sandboxed.** Every new `crates/biorouter-server/tests/*.rs` declares `#[path = "../src/test_sandbox.rs"] mod test_sandbox;`, which [`every_test_binary_is_sandboxed.rs`](../../crates/biorouter-server/tests/every_test_binary_is_sandboxed.rs) enforces [C]. A CLI binary that spawns `CARGO_BIN_EXE_biorouter` sets `BIOROUTER_PATH_ROOT` to a temporary folder for the child, because the CLI's own sandbox covers its library tests, not a child process [I]. No test reads the person's real configuration, data folder, keychain or microphone.
6. **CPU only in CI.** Engine tests set `use_gpu = false`. Whether hosted macOS arm64 runners expose Metal is unmeasured [I]. Metal is proved by `smoke_mac`, Tier 2 and the checklist.
7. **Tests pin the measured side.** Where the research disagreed with itself, the tests encode what was measured on real binaries: timestamps on (small.en collapsed on 12 of 49 real utterances with them off and 2 of 49 with them on [M]); the voice detector always on, including on the retry; greedy decoding; the prompt as `prompt_tokens`, never `initial_prompt`; and no Electron test ever passes `--use-fake-ui-for-media-stream`, because with it Electron skips the permission handler entirely (zero handler calls; audio and video granted under a deny all policy) [M].
8. **No accuracy claim, ever** (DD-95). No accuracy claim about the product appears in user documentation, release notes, the announcement or the interface, and synthetic speech never supports one; the owner decided on 2026-11-05 that this is permanent, because no lab recording set will exist (O-23). Design measurements in `docs/dictation/` and `docs/research/` stay, labeled [M] with their date.
9. **What "works when it appears" means for tests** (DD-94). A control, command or route merges only with a test that drives it end to end on the surfaces it reaches: an integration binary for a route, a Playwright run in the dev app or against `serve` for a control, a real model `#[ignore]` run recorded in the pull request for transcription quality, or a recorded checklist row for what only a person can do. Controls that PR-18 to PR-20 hide on `isBrowserSurface()` carry a vitest that pins them hidden there; PR-21 replaces that test with the `serve` job's browser run.

**The gate of DD-57 (M-21).** `learn_from_chats` ships on only if the extractor reaches precision 0.8 or more at `seen ≥ 2` on the person written messages of 200 of the owner's sessions. Those sessions are the owner's own chats and may hold patient data, so the run needs the owner's consent and the owner's own labelling time (O-44, 2026-11-10): the owner decided on 2026-11-05 (O-23) that it runs on the owner's machine, excluding sessions that used a private model or hold patient data. The run is local and nothing leaves the machine:

1. The owner copies `sessions.db` to a private folder with Biorouter closed.
2. An `#[ignore]` test, `crates/biorouter/tests/dictation_extractor_precision.rs`, reads that copy (path in the test only variable `BIOROUTER_EXTRACTOR_EVAL_DB`), takes the 200 most recent sessions whose `privacy_tier` is public, so none that used a private model, leaves out every session the owner names as holding patient data, runs `extractor::candidates` over person written user messages only, applies `seen ≥ 2` across sessions, and writes one CSV row per listed candidate to a temporary folder outside the repository. A row holds the candidate token and its count, never the message around it.
3. The owner, and only the owner, labels each row "would add" or "would not" (O-44).
4. Precision is the share labelled "would add". The PR-24 description records the date, the count of candidates and the precision, never a term.
5. At 0.8 or more the default is on; otherwise it stays off.

M-21 was not run before PR-24 landed (`491246227`), so PR-24 ships it off (`LEARN_FROM_CHATS_DEFAULT = false`), the Dictionary page shows **Also find terms in my messages automatically** off with MSG-LEARN-FROM-CHATS-HELP, and the reason is recorded in [dictionary](dictionary.md#the-m-21-gate): the owner decided on 2026-11-10 that the run waits for the owner's own labels on candidate tokens from eligible chats (O-44). Steps 1 to 4 stay the procedure for a later run.

On public text, a close variant of these candidate rules reached 74 % to 75 % precision at `seen ≥ 2`, and requiring a second sighting did not raise precision (it cut volume about six times) [M]. So the default most likely ships off unless the owner's own sessions do better [I].

## The privacy test suite

Each privacy invariant is held by named tests. [Dictionary](dictionary.md) states the invariants and why; this table is where they are proved. A pull request that weakens one of these tests changes an invariant and needs the owner.

| Id | Invariant | Named tests | PR | Runs in |
|---|---|---|---|---|
| P-1 | Audio stays in memory in Biorouter's processes on the transcribing host: no temporary file, log line, diagnostics entry or session row; the stream buffer is zeroed at finish, cancel or the 60 s expiry; no off machine engine in v1. A crash of the engine worker, the process that holds the audio and is expected to abort (DD-4), writes no memory to disk: on Unix its core file limit is zero, soft and hard, which systemd-coredump honors too, and on Linux it is not dumpable, which also keeps a debugger of the same account out; on Windows it turns off Windows Error Reporting for its own crashes (`SEM_NOGPFAULTERRORBOX`) and asks that a report still made, as for a fail fast abort, leave out the heap (`WER_FAULT_REPORTING_FLAG_NOHEAP`). | degraded speech | pink noise at SNR 10 dB and a synthetic room with RT60 about 0.4 s, from the clean evaluation clips with a fixed seed | Tier 1 only |
| MP3, M4A and Ogg | the tone, encoded by `ffmpeg`; the MP3 decodes, the M4A and Ogg are refused | Tier 1 only |

**Rules.**

- `.gitattributes` gains `vendor/whisper.cpp/source/** -text`, `*.wav binary` and `*.flac binary`, beside today's `vendor/computer-use/source/** -text` [C]. The fixture hash test turns a CRLF or LFS pointer checkout into a named failure instead of a model that loads garbage.
- No tokenizer text is committed. For both vocabularies, `vocab.json`, `tokenizer.json` and the decoded vocabularies spell the former upstream's name as BPE pieces; `merges.txt` does so for the multilingual vocabulary that turbo uses, while the English `merges.txt` of small.en has no match [M]. Golden BPE ids are committed as numbers. The binary fixtures are safe because the retired name guard reads tracked text with `git grep -I`, which skips them [C, M].
- No real transcripts and no clinical audio are committed. Accuracy audio lives in release assets (Tier 1). The Fareez et al. 2022 subset that Tier 2 and M-22 add is built on the maintainer's machine by `scripts/dictation/fetch-fareez-subset.sh` (PR-14) and is never committed or cached in CI; only its pins, manifest and term list are committed. MultiMed is not used for any test or measurement (O-38).
- `assets/english-words.zst` is product data, not a fixture, and sits outside the budget. Because it is compressed, `git grep -I` cannot see inside it, so the generator under `scripts/dictation/` has a check mode that regenerates it from its pinned source, compares the bytes, decompresses it and scans every line with the retired name guard's own patterns. That check runs in `guards`.
- Every golden table and term list in a test is screened by the retired name guard before commit, as `guards` does anyway.

### Tier 1: networked nightly accuracy

`dictation-accuracy.yml` runs on `ubuntu-latest`, CPU only, and executes the `#[ignore]` tests that need a real model or an encoder:

```bash
sudo apt-get install -y ffmpeg
cargo test -p biorouter-dictation --features engine --test model_download_live -- --ignored
cargo test -p biorouter --features local-dictation --test dictation_accuracy -- --ignored
cargo test -p biorouter-cli --test dictation_cli -- --ignored --test-threads=1
```

The leaf crate's other ignored test, `jfk_latency_real_models` in `dictation_engine_offline.rs`, is a measurement by hand that needs `BIOROUTER_DICTATION_BENCH_DIR`, so Tier 1 does not run it; the JFK sentence is checked by `dictation_accuracy.rs` instead. `dictation_accuracy.rs` lives in `crates/biorouter/tests/`, not in the leaf crate, so it builds the dictionary's bias set through `bias::bias_set` like the product does: a leaf crate test cannot reach the core crate, and calling `EligibleEntries::new_filtered` directly would fail `eligible_entries_are_built_only_by_bias_set`. The last command covers the MP3 decoding case, the M4A and Ogg refusals and `transcribe` with the real models, and from PR-14 the agent shell rule on reversed speech (the reversal is made from `jfk.wav` at test time).

1. **Models.** The test installs each model through the leaf crate's own installer into `$RUNNER_TEMP/models`, which `actions/cache` restores by the catalog's SHA-256, and points `BIOROUTER_DICTATION_MODELS_DIR` at it. A cache miss therefore also exercises A-1's download path with the product's own pins.
2. **Evaluation set.** The PriMock57 subset: 60 utterances with 85 occurrences of 26 drug names, and 16 gaps where the recorded speaker is silent (10 of room tone, 6 where only the other party bleeds in), about 7 MB of FLAC, CC BY 4.0. A-1 publishes it before PR-12 merges as the `BaranziniLab/biorouter-models` release `eval-primock57-subset-r1` (a FLAC tarball, `ATTRIBUTION.md` and its SHA-256; clipped from PriMock57 at commit `cd2ac707`, cut at TextGrid boundaries ±250 ms), under the `eval-<name>-r<n>` tag scheme with its own `catalog/eval-*.json` beside the `stt-` releases (DD-16). The test pins its SHA-256 and reads it from `BIOROUTER_DICTATION_EVALSET`, a variable only this test reads.
3. **Arms.** Each model runs twice, both times with the voice detector, which is always on: with no dictionary (the baseline arm), and with the subset's 26 terms as the dictionary through the shipped mechanism (the DD-44 default of the commit under test). Each arm runs on the clean utterances and on the seeded SNR 10 and reverb copies the test generates; the 16 gaps run as recorded.
4. **Scoring.** Strict recall is the share of reference term occurrences whose canonical written form appears exactly in the output. A collapse is an output of 25 % or less of the reference's words. A false correction is a change in the transcript's `changes` list that turns a correct reference word into another. A spurious insertion is a dictionary term in the output where the reference has none (the 16 gaps included).
5. **Floors.** On the clean utterances with the dictionary: strict recall 70 % or more for `whisper-small.en-q8_0` and 75 % or more for `whisper-large-v3-turbo-q5_0`. On the 16 gaps, in both arms: nonspeech outputs 0 of 16 (turbo at most 1 of 16). On every condition: 0 collapses; 0 false corrections; spurious insertions with the dictionary no higher than in the baseline arm. These are the starting floors; the first run with the shipped mechanism sets them again, and the new values are written into the test with the date. Recall on the degraded copies is reported and not gated. **Set again on 2026-11-06 (PR-14b)** for the shipped default, the token prompt alone ending in a period, with correction, from runs on Metal and on the M4 Max's CPU [M]: strict recall on the clean utterances 62 of 85 for `whisper-small.en-q8_0` and 70 of 85 for `whisper-large-v3-turbo-q5_0` (`DICTIONARY_RECALL_FLOORS`: 4 hits, 5 points, under the lower of the two runs, which measured 67 and 66, and 74 and 75); 0 collapses and 0 false corrections on every condition; spurious insertions 0 on the clean utterances and the gaps, as in the baseline, and on the degraded copies at most what was measured (`DEGRADED_INSERTION_FLOORS`: small.en 0 on SNR 10 and 3 under reverb, turbo 1 on SNR 10 and 0 under reverb). On those copies the prompt turns a garbled `Paracetamol` into another listed drug (`Piriton`, `Cetraben`), which the baseline, with no list, writes as ordinary words, so "no higher than in the baseline arm" cannot hold there with any prompt. The dictionary arm now runs the same three conditions as the baseline; until PR-14b it ran the clean utterances only. No x86 run has measured these values yet, and the degraded copies' insertion counts have no headroom, so from 2026-11-06 a count above `DEGRADED_INSERTION_FLOORS` fails the run only on Apple Silicon, where they were measured (`DEGRADED_FLOORS_MEASURED_HERE`); on any other machine, the hosted x86 runner included, it is a `::warning::` in the log and is recorded in `dictionary-summary.json` (`insertion_floor`, `insertion_floor_enforced`), as a red result on a degraded copy blocks nothing (below). The first hosted run's counts set x86 floors, written into the test with their date. Recall, collapses, false corrections and the clean and gap insertions fail on every machine.
6. **Output.** Per term tables, the full transcripts and the counts are uploaded as artifacts. The job fails only on a default model's floor; anything else is a `::warning::` annotation.

Schedule: small.en nightly and on pull requests that touch the engine; turbo weekly and on dispatch. One model's run is 2 arms of 60 utterances in 3 conditions plus the 16 gaps, about 392 decodes. At the measured 0.73 s (small.en q8_0) and 9.0 to 9.6 s (turbo) per utterance on 4 CPU threads [M], that is about 5 minutes for small.en and about an hour for turbo on comparable hardware; hosted runners are slower [I], so the turbo job's timeout is 240 minutes [I]. PR-12 lands the workflow with the baseline arm's floors (nonspeech, collapses) and records the no dictionary baseline; PR-14 adds the dictionary arm and its floors.

### The real speech regression gate

A release that changes the engine, a pin or a recognition default is published only when Tier 2 shows, at fixed model and settings against the previous dated table:

1. on the PriMock57 subset, on the Fareez subset and on the synthetic dictation set, each taken alone, no strict recall regression of more than 5 points (a set of about 80 occurrences cannot resolve less), and no paired sign test that finds it worse at p < 0.05;
2. 0 nonspeech outputs with voice detection on the synthetic nonspeech clips, and on the 16 PriMock57 gaps 0 of 16 (turbo at most 1 of 16, Tier 1's floor);
3. 0 false edits on the synthetic probe clips and on PR-14's correction negatives;
4. 0 collapses.

The first Tier 2 run sets the baseline and no comparison applies. Tier 1's floors hold between releases.

### The M-22 decision and its fallback (DD-44)

M-22 runs on public recordings and synthetic speech, because the owner decided on 2026-11-05 that Biorouter records no real voices for evaluation (O-23), which withdrew M-9 and its lab set, and that its tests and measurements use only clearly licensed public recordings and synthetic voices (O-38). Arms: no dictionary, token prompt, decoder bonus, both, and each with correction, on turbo and small.en; `temperature_inc` 0 against 0.2; timestamps on and off for small.en. Material:

- the PriMock57 subset that Tier 1 uses (CC BY 4.0; 85 drug name occurrences over 26 terms, and its 16 gaps);
- a subset of the Fareez et al. 2022 simulated clinical interviews (CC0 on the figshare article [R]): utterances of 2 to 25 s that hold drug names, cut at forced alignment boundaries; its first build, from 24 interviews, gave 80 clips holding 104 term occurrences [M, 2026-11-06];
- synthetic speech from [speech model benchmarks](../research/voice-dictation/speech-model-benchmarks.md): the synthetic dictation set (14 terms, five of them gene symbols, 81 occurrences per model, generated by script and never committed), the synthetic nonspeech clips, the 75 synthetic probe clips and reversed speech.

MultiMed is not used, decided by the owner on 2026-11-05 (O-38), although the research measured it on 2026-11-04. Gene symbols on real speech are therefore unsettled: no licensed public recording of real speech with gene symbols exists, and the owner ruled out lab recordings (O-23). M-22 measures gene symbols on synthetic speech only, and its record says so.

**Fetching the Fareez interviews.** The research never downloaded them. PR-14 adds `scripts/dictation/fetch-fareez-subset.sh`, run by the maintainer, which:

1. downloads `Data.zip` (1,034,153,474 B) through the figshare API's own download URL, `https://ndownloader.figshare.com/files/30598530`, because the `figshare.com/ndownloader/...` web path answers a scripted client with an AWS WAF challenge (HTTP 202) [M];
2. records the figshare article's license and stops unless it reads CC0;
3. checks the archive's SHA-256 against the pin PR-14 recorded at its first download, `20ef65540768d49ab6368672994aaef6acb21117d139e5d91e76a32432da951e` (the figshare MD5 matched too), and reads the CC0 license from article 16550013;
4. aligns the transcripts, which carry no timestamps [R]: the aligner PR-14 named is Biorouter's own `biorouter transcribe --no-dictionary` with the catalog's turbo model, pinned by the catalog's SHA-256, then a `difflib` word alignment of the human transcript against its output (`scripts/dictation/fareez_subset.py`), so no new aligner dependency exists; it cuts the drug name utterances with `ffmpeg`, by default from 24 interviews, most terms first;
5. writes each clip's SHA-256 to a manifest (`scripts/dictation/fareez-subset.manifest.jsonl`, the public one, with no reference text), beside the term list `scripts/dictation/fareez-terms.txt`.

The script, the pins, the manifest and the term list are committed; audio, transcripts and alignments are not, and CI never caches them. Its first build gave 80 clips holding 104 term occurrences, none dropped by the retired name guard [M, 2026-11-06]. A transcript line or term that is committed passes the retired name guard first, because real transcripts have tripped it [M].

The rules below are fixed before the numbers exist, because DD-44 rejects choosing after seeing them:

1. **Channels.** The combination of token prompt and decoder bonus stays the default only if, on both models: its strict recall pooled over the two real sets is no more than the margin below either channel alone, where the margin is 3 points when the two sets together hold at least 160 term occurrences and 5 points otherwise (a set of about 80 cannot resolve less); its strict recall on the synthetic dictation set is no more than 5 points below either channel alone; a paired sign test does not find it worse than either at p < 0.05 on the real sets; and its counts of nonspeech outputs (the 16 gaps and the synthetic nonspeech clips), insertions on the probe clips and reversed speech, and collapses are no higher than either channel's. Otherwise the declared fallback ships: the token prompt only, with the decoder bonus built but off. If the Fareez subset cannot be built (the download, the license check or the alignment fails), M-22 runs on PriMock57 as its only real set with the 5 point margin, and its record says so.
2. **Other settings.** For `temperature_inc` and timestamps, the current default stays unless the alternative passes the same test and is strictly better on at least one gate metric. Browser audio processing on against off (DD-64) needs speech through Biorouter's own capture path, which only a recording of a person would give; it is recorded as unsettled for that reason, and DD-64's defaults stand unmeasured.
3. **Record.** The result, the arms, the real sets used with their occurrence counts, and the date go into [speech model benchmarks](../research/voice-dictation/speech-model-benchmarks.md), with the statement that gene symbols on real speech were not measured; a changed default lands in its own pull request with Tier 1 floors set again. No figure from M-22 appears in user documentation, release notes, the announcement or the interface (DD-95).

**Outcome.** M-22 ran on 2026-11-06 and the declared fallback ships: the token prompt only, with the decoder bonus built but off. PR-14b made it the compiled default and set Tier 1's floors again ([Tier 1](#tier-1-networked-nightly-accuracy), item 5). Since then `m22_arms`' "both" arm is `BiasChannels::BOTH`, and every arm that carries a prompt sends it with the tail.

**The prompt tail (PR-14b).** PR-14's live check found that the token prompt drops Whisper's final sentence punctuation, and a text prompt ending in a period restored it. `prompt_tail` (`#[ignore]`, in `dictation_accuracy.rs`) runs the shipped channels with the period after the prompt's best term against without it, and no dictionary, on M-22's material, both models. The rule, fixed before the numbers: on each model, a clip lost its final punctuation when the no dictionary arm's raw text ends in `.`, `?` or `!` and the no tail arm's raw text, not empty, does not; the tail is adopted only if, on both models, it restores final punctuation on at least 90 % of those clips, its strict recall pooled over the real sets is no more than 3 points below no tail, its synthetic recall no more than 5 points below, and its insertions are no higher on the probe clips nor, taken on their own, on reversed speech. On 2026-11-06 it passed on both models and the tail ships (DD-45); the numbers are in [speech model benchmarks](../research/voice-dictation/speech-model-benchmarks.md#addendum-2026-11-06-the-prompt-tail-and-the-shipped-defaults-tier-1-floors).

### Long dictation (DD-50, M-19)

The split rule (ask for voice segments once 8 s are buffered; queue closed segments of 25 s or less split at the longest pause; `no_context = true`) has unit tests and PR-15's synthetic measurements ([engine and models](engine-and-models.md#lifecycle-and-deadlines)), but no measurement on real continuous speech. M-19 measures it through the real streaming path: an `#[ignore]` test in `dictation_routes.rs`, `long_dictation_replays_in_real_time`, not built yet, starts the routes in process with a real model, replays each recording in 100 ms chunks batched every 2.5 s at real time pace, finishes, and records the Stop to text time and the boundary word loss (reference words within 1 s of a split that are missing from the output). Recordings: continuous PriMock57 doctor channels of 60 to 180 s. It runs on Metal and on an x86 CPU. The result is recorded and blocks announcing v1; a boundary loss clearly above the deletion rate inside segments reopens DD-50 [I].

### Rollback

| Situation | Action |
|---|---|
| An organization must stop dictation now | managed `dictation.enabled: false`, or `dictation.capture: false` for live microphones only; every door refuses with MSG-POLICY or MSG-POLICY-CAPTURE without a new build |
| A `serve` host must stop browser installs | `biorouter serve --no-dictation-install`, or `BIOROUTER_DICTATION_BROWSER_INSTALL=false` |
| A person wants dictation gone | **Remove** in Settings or `biorouter dictation remove <id>` (the voice detector goes with the last speech model); turn off **Suggest dictionary words from my chats** |
| A build must ship without the engine | build `biorouter-cli` and `biorouter-server` with the default `local-dictation` feature off (and the CLI's `dictation` feature); `dictation status` reports `compiled: false` and every surface shows MSG-NO-ENGINE |
| A surface regresses after release | revert the pull request that made it work and cut a patch release; there is no flag to flip |
| A published model file is wrong | releases are immutable, so publish a new `stt-<id>-r<n+1>` tag, pin it in an app release, and keep the old hash in `accepted_sha256` only if the old file was good; nothing updates an installed model automatically |
| An engine pin bump regresses | revert the bump; the previous pin's Tier 1 floors and Tier 2 table still hold |
