# Local dictation implementation plan

> **What this is.** The master plan for local voice dictation in Biorouter: a microphone beside **Send** in every Biorouter composer, a speech engine built into Biorouter's own binaries, speech models a person chooses to install from the Baranzini Lab's GitHub, a personal dictionary with a left sidebar page and an agent extension, and a working path or an honest message on every deployment.
> **Status:** Current: the plan being built on branch `feat/local-dictation`, pull request by pull request in the order of the delivery plan
> **Audience:** the owner, whose decisions of 2026-11-05 are recorded under [owner decisions](#owner-decisions); the developers who build the pull requests; reviewers of each pull request.

Biorouter has no local speech recognition today. What it does have is the inherited cloud dictation: a daemon route that forwards audio to OpenAI or ElevenLabs on the daemon secret alone, with no privacy tier, no proof of a person and no off switch, wired to a settings folder that nothing mounts. The owner asked for dictation that runs on the person's own hardware, learns their vocabulary, works on every way Biorouter is deployed, and never downloads a speech model unless the person asks for one. This plan targets `main` at `52917f33e`, three commits after the v1.94.1 tag (the workspace version is 1.94.1). It states how each requirement is met, how dictation works on each of the 20 surfaces (the owner excluded one, S13, Jupyter AI), the decisions behind the design, and the pull requests that build it. Four area documents carry the detail: [engine and models](engine-and-models.md), [dictionary](dictionary.md), [surfaces](surfaces.md), and [testing and release](testing-and-release.md). The evidence behind the engine and model choices is in [speech model benchmarks](../research/voice-dictation/speech-model-benchmarks.md) and [dictation tools survey](../research/voice-dictation/dictation-tools-survey.md).

## Summary

Biorouter compiles whisper.cpp (vendored at commit `4da27c41cebadb3cbbcd2563e9c7cbc8d84bdcad`) into both `biorouter` and `biorouterd` and runs it in a worker process that the running binary starts from itself, so an engine crash or an unsupported processor never takes a chat down. One rule reaches every surface that offers dictation: **capture where the person is, transcribe where the agent and the dictionary live.** Biorouter's own pages (the desktop app, a `biorouter serve` browser, Crew's boxes) record in the browser engine and stream 16 kHz audio in small HTTP uploads to their daemon. The terminal records in a child of `biorouter` and transcribes in process. Jupyter AI gets no dictation: the owner decided on 2026-11-05 that no microphone or dictation feature is built for Jupyter (O-30), so Biorouter adds no control there. Composers Biorouter does not own (ACP editors, app pages opened in a browser, other applications) get **Dictate to clipboard** from the desktop tray or `biorouter dictate --copy`.

Speech models are never part of an install or an update. A person installs one, verified against a SHA-256 pin compiled into Biorouter, from immutable releases of `BaranziniLab/biorouter-models` into Biorouter's own per user data folder. The default is `whisper-large-v3-turbo-q5_0` on Apple Silicon and `whisper-small.en-q8_0` on other computers, each with the `silero-vad-v6.2.0` voice detector.

Each account has one personal dictionary. Dictation biases recognition toward its terms with a token prompt and a decoder bonus, then corrects with guarded exact matching. The person edits it in a new **Dictionary** page in the left sidebar, in the terminal, and from any chat. A `dictionary` capability lets the agent ingest terms from conversations. By default it follows memory's own protocol (`on_request`, decided by the owner on 2026-11-05, O-3): a term the person asks the agent to add, or agrees to when the agent offers it, goes live at once, and every other agent term waits for the person's review, because the dictionary is machine wide. Waiting for review always (`suggest`) and immediate writes (`add`) are the person's settings. Entries learned in a private chat never shape dictation aimed at a public model, because Whisper copies its prompt into the transcript on silence, and a private entry carries the institutions of the chat it came from, those behind the chat's model and those whose connectors the chat touched, so it never shapes dictation aimed at another institution's model (O-32, O-35, O-36). Privacy tiers here, as everywhere in Biorouter, are a safety boundary against mistakes by cooperative actors, not a security boundary against a determined adversary.

Delivery is 31 pull requests in eleven milestones (M0 to M10); PR-07 and PR-32 keep their ids and are withdrawn by the owner's decisions O-15 and O-30 (2026-11-05). The engine and its load time guards land together, file transcription and the dictionary work from the terminal before any desktop control appears, and a control appears only in the pull request that makes it work. Version 1 is announced when every surface other than S13, which the owner excluded, has a passing section in the manual test checklist and the blocking measurements are recorded.

## Architecture

### The rule that reaches every surface

1. **Capture where the person is.** Only a process in front of the person opens a microphone: the desktop renderer, a browser tab, a capture child of `biorouter` on a person's terminal. A daemon never opens one. On a server it would record the wrong room, and on macOS the permission system would charge whichever process started the daemon [I].
2. **Transcribe where the agent and the dictionary live.** The process that owns the target chat transcribes with its own account's model and dictionary: the daemon for Biorouter's pages, `biorouter` for terminal front ends. So the bias set is decided from the target chat's tier on the same host, and only text crosses into a chat.
3. **One engine, one pipeline.** Every transcription runs the same Rust code: voice detection, the bias set filtered by tier, the token prompt, the decoder bonus, decoding, the echo guard, and correction. The code lives in a leaf crate linked into both binaries, so no surface depends on a package another surface lacks. Terminal capture lives in a second crate that only `biorouter` links (DD-5).
4. **One dictionary per account.** `<config>/dictionary/` is read and written by the daemon, the CLI and the `dictionary` capability under one file lock. Two machines have two dictionaries; export and import move terms between them.
5. **Composers Biorouter does not own get the clipboard.** The desktop's **Dictate to clipboard** and `biorouter dictate --copy` bring the same engine and the public part of the dictionary to any application; private terms join only when the person includes them for one recording (O-8).

### Processes and data flow

```text

   VAD split (segments <= 25 s) -> bias set filtered by tier (EligibleEntries) -> rank
   -> token prompt (top 30, <= 150 BPE tokens) + decoder bonus (whole bias set)
   -> greedy decode, timestamps on -> nonspeech filter and echo check (one retry without the prompt)
   -> correction (aliases, exact keys, guarded fuzzy) -> text and a list of changes
```

One supervisor per host process (`biorouterd`, an interactive `biorouter`, `biorouter acp` once ACP audio exists), held in a `OnceLock` like `llamacpp_sidecar::global` [C `llamacpp_sidecar.rs:369`]. A worker is the running binary started again with a hidden first argument, so nothing is discovered on disk, and a CLI reached through a symbolic link or a lone Windows `.exe` copy works [M]. `biorouter-crew` never links the engine.

## Delivery plan

### Rules for every pull request

1. **It works when it appears.** A control, command or route ships in the pull request that makes it work end to end on the surfaces it touches. Nothing is merged behind a release flag, and nothing is shown that would answer "not implemented". Pull requests with no visible feature ship hardening, guards or an interface that their own tests exercise.
2. **Its gates come with it.** The CI step, guard script or smoke line that proves the change lands in the same pull request. A pull request that changes the engine or its build dispatches `rust.yml` before merge, because no pull request job links the Linux or Windows binaries.
3. **Offline by default.** New `tests/*.rs` binaries run in CI's loopback only integration step with no exclusion line; anything that downloads a model is `#[ignore = "downloads a pinned speech model"]`. Every new server test binary declares `mod test_sandbox;`. Keyless daemon cases get their own binary, because the user action digest is a process global `OnceLock`.
4. **Docs and guards.** Each pull request updates the documents it makes stale and passes the retired name guard, `scripts/verify-docs.sh` and `python3 scripts/docs-lint.py` (the one that checks links) for the docs it touches, and for frontend changes `npm run lint:check` and `npm run format:check` (CI does not run Prettier).
5. **Release.** An app release may carry any prefix of the sequence. Version 1 is announced under DD-94.

The commit that adds these plan documents also adds their index rows: a row in `docs/README.md`'s by topic table and in `docs/organization.md` §2 for `docs/dictation/`, and a row in `docs/research/README.md` for `docs/research/voice-dictation/` (whose opening sentence, which names coding agents as the folder's only topic, changes with it), because a new folder needs its index rows the day it lands.

| Docker (S16) | `biorouter` in the container | A data volume at `/home/biorouter/.local/share/biorouter`, or a read only mount at `/var/lib/biorouter/dictation/models` | `docker run … <image> dictation install`, or the browser's Settings through `serve` |
| WSL (S19) | The WSL Linux account | `~/.local/share/biorouter/dictation/models/` inside WSL | `biorouter dictation install`, or `--from /mnt/c/…` to reuse a Windows side download |
| External backend (S17) | The account that runs the backend | The backend host's folder, not the laptop's | Settings on the laptop with that server's key, or the host CLI |
| Air gapped hosts (S20) | As the surface | As the surface | `biorouter dictation install --from <file\|dir>`, or files placed in the folder and **Rescan** |
