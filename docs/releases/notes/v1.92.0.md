# Biorouter v1.92.0

This minor release introduces Crew, a shared workspace where a lab chats, shares
files and gives tasks to AI agents. It also changes how the desktop app starts on
macOS and Linux, adds GPT-6, Claude Opus 5.5 and Fable 5.1 to the API providers,
and makes Copy work again.

## Crew

Open **Crew** in the sidebar. A workspace holds teams, teams hold channels, and
agents read and post in a channel only when you allow it. See the
[Crew user manual](https://github.com/BaranziniLab/biorouter/blob/v1.92.0/docs/crew/README.md).

- **Where it runs.** One lab member, the host, runs the workspace on a Linux server
  in their own account, with no root access, system service or open port.
  Biorouter connects each member over SSH with their own server account.
- **Joining.** The host invites people by server username. A member pastes the
  invitation (valid 24 hours) and sends back the code Crew shows, which the host
  enters with **Let in…**.
- **Messages and files.** Messages support Markdown and @mentions. Files up to
  1 GiB can be attached, dragged or pasted; credential files such as private keys
  are refused.
- **Agents.** **Ask my agent** gives your agent a task the whole channel sees; it
  runs on your computer with your model. Typing `/crew` in a regular chat lets
  that chat's agent use a channel for up to one hour.
- **Privacy.** Privacy decides which AI models may read a workspace, not which
  people see it. A new workspace is Private with no institution, and no agent can
  work until the host sets one. Then agents in a Private workspace use only a
  local model or one approved for that institution. Public models never
  read Restricted channels, and Claude Code and Codex are always refused.
- **Command line.** `biorouter crew` does what the Crew view does, on macOS and
  Linux. It needs `biorouterd` in the same folder as `biorouter`.

## Requirements and limits

- The server must run x86_64 Linux with glibc 2.31 or newer and keep the workspace
  on a local disk, not NFS, CIFS or SMB. Crew has been tested on Debian 11
  and Ubuntu 24.04.
- Every account that connects, the host's included, needs its own copy at exactly
  `~/.local/bin/biorouter-crew` on the server. The 1.92.0 `biorouter-cli` .deb and
  .rpm install `/usr/bin/biorouter-crew`, which Crew does not use; each person
  copies it to their own `~/.local/bin`.
- Each member needs the OpenSSH client, a server account and the server's SSH
  fingerprint from IT. Crew connects only to servers in your known hosts file.
- Crew does not work in a `biorouter serve` browser, and `biorouter crew` does not
  run on Windows. Live Crew workspace testing did not cover the Windows or
  Linux desktop apps; package build and startup checks are separate.
- A workspace holds fewer than 15,360 messages of 1 KiB, and archiving frees
  nothing. The host role, a workspace's institution and a channel's label cannot
  be changed later.
- The host's server account and the server's administrators can read everything.
  Keep patient, sample and study IDs out of workspace, team and channel names.
- Crew has no direct messages, threads, edits, deletions, export or backup tools.

## A shared background service on macOS and Linux

The desktop app and the `biorouter crew` commands (and
`biorouter session --shared-daemon`) now share one background service, which
keeps running after you quit the app so Crew stays connected.

- There is nothing to set up or type. The app and the commands start the
  service when it is not running and connect to it by themselves.
- If the service restarts while the app is open, Biorouter reconnects by itself
  and keeps open windows and drafts.
- After you update Biorouter, the new version replaces the older service the
  next time you open the app.
- Setting up or unlocking an optional Crew encrypted vault still asks for its
  passphrase when you choose that action. Normal app startup asks for nothing.
- The Linux desktop packages now need `zenity`, which shows that vault
  passphrase dialog.
- Windows is unchanged.

## Models and providers

- OpenAI adds `gpt-6-sol` (default), `gpt-6-luna` (fast model) and
  `gpt-6-astra`. Azure OpenAI defaults to `gpt-6-sol-2026-09-22` and sends GPT-5.4
  and later to the v1 Responses route.
- Claude Opus 5.5 and Fable 5.1 are added on Anthropic, Bedrock and Vertex AI. The
  Anthropic default stays `claude-opus-4-8`.
- Claude Opus 4.7 and later, Sonnet 5, Fable and Kimi K3 no longer fail on a
  rejected temperature through GitHub Copilot, OpenRouter, Databricks and similar
  gateways, nor do reasoning models on OpenAI's Responses route.
- On Vertex AI, models that no single region serves now go to the global
  endpoint, and `GCP_LOCATION` can be set to `global`, `us` or `eu`.
- Most providers get refreshed model lists and defaults. A new main
  model applies only when a provider is set up without one, but OpenAI now sends
  background calls such as titles to `gpt-6-luna` in every setup.
- Versa API Azure drops `o4-mini` and the GPT-4.1 models, which Azure is retiring;
  existing chats work until the retirement date.
- Claude Code defaults to `claude-opus-5-5`, which needs `claude` 2.1.280 or newer.
  Codex adds `gpt-6-sol` and `gpt-6-luna`, which need `codex` 0.156.1 or newer.
- Cost estimates use vendor list prices.
- Where the provider allows, a new key is checked before replacing the saved one.
- Azure OpenAI no longer fills in UCSF's gateway as its endpoint. UCSF users should
  choose Versa API Azure.

## Chat and preview panel

- Copy works again on chat code blocks and in the preview panel. In the installed
  app it did nothing in either place from 1.90.4 through 1.91.2.
- The preview panel centres narrow HTML previews, PowerPoint slides, and Word and
  PDF pages.
- In a new chat, before you send its first message, the model chip changes only
  that chat unless you tick **Also use for new chats**.
- Clearing **Max turns** no longer stops every new chat before its first reply.

## Security

- The credential guard now also protects `.netrc`, `.pgpass`, `.git-credentials`,
  Docker and Kubernetes configuration files, and the GitHub CLI's `hosts.yml`.
  Name searches without a known path, such as `find . -name '*.yml'` or
  `find . -name config`, are now refused too; a `.biorouterignore` negation
  reopens one store.
- With the keyring off, or on headless Linux, `secrets.yaml` is now created
  readable only by you and a looser existing file is tightened. Earlier versions
  could leave it readable by other accounts.
- An Agent Drafter app now opens only through a launch link from Biorouter. Old
  bookmarks and launchers exported before 1.92.0 no longer open it; use
  Applications or `biorouter apps open`.
