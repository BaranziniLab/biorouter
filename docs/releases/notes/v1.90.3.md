# Biorouter v1.90.3

A patch release with a long tail: twenty-seven pull requests merged on 8–9 September, most of
them found by driving the real app rather than by reading it. Two of them fix things a user of
the terminal CLI hits on the first command.

## The terminal CLI refused a configured provider

Since 1.89.0, `biorouter`, `biorouter session`, `biorouter run` and `biorouter session --resume`
all answered *No provider is configured* on a fully configured install, and `biorouter configure`
could not change that: the guard that refuses to create a session row before a provider exists was
handed only the `--provider`/`--model` flags, never the default saved in `config.yaml`. Only
`run --no-session` worked, because it skipped the guard. The guard now resolves the configured
default itself (and the environment variable), so no call site can forget it, and the refusal on a
genuinely empty install names commands that actually take `--provider`.

`biorouter serve` had a second defect on macOS: it derived the interface bundle and the daemon's
location from the path it was *invoked* through, which is the `~/.local/bin/biorouter` symlink the
in-app CLI installer creates — so it found neither. Paths are now resolved through the real
executable on every platform. Both fixes were exercised end to end: real turns on the bare command,
and `serve` through a symlink answering 401 without its token and 200 with it.

## Deleting a schedule deleted its workflow

A schedule created from a workflow's own row pointed at the user's workflow file rather than a
copy, and deleting the schedule removed that file. Schedules now record whether the scheduler owns
their source, and deletion can never unlink a file outside the scheduler's own directory, whatever
the record says. A refused schedule name also carries the daemon's reason instead of *Unexpected
response format*.

## Model catalogs

The Claude Code and Codex providers advertise what the vendors' CLIs serve today: Claude Fable 5.1
(default), Opus 5, Sonnet 5 and Haiku 4.5; GPT-6 Astra (default), the three GPT-5.6 variants,
GPT-5.5 and GPT-5.3 Codex Spark. Retired ids are gone. The two new defaults need `claude` 2.1.251+
and `codex` 0.153.4+; on an older CLI the vendor's own upgrade message is shown, unwrapped from its
JSON envelope.

## Provider configuration and first run

Providers are configured on three tabs — Local, Institutional (UCSF, with room for other
institutions) and Public, where the coding agents come first — and first-run onboarding uses the
same surface; a new user can enter the app before choosing a provider, and the composer says so.

## One measure and one vocabulary

Settings, Chat history, the Scheduler, Workflows, Extensions, Skills and Built apps all sit on the
760px chat measure under one page header, with sentence-case actions, no state-dependent fills,
no focus fill on tabs or panels (the underline is the indicator), a quiet focus edge on
keyboard-scrollable regions, legible chat tab labels, and a not-found page inside the shell for an
unknown address. The composer's chip and gauge now state the model a chat actually runs on, with
a one-line note when a private chat cannot use the selected public model.

## Removed: MCP apps

The "MCP apps" surface inherited from the upstream codebase — a sidebar row, a page and a proxy
for interactive apps declared by MCP servers — was never a Biorouter feature and is gone. Built
apps, the Auto Visualiser and the artifact panel are unaffected; none of the ecosystem extensions
used it.

## Reliability

Four CI races were fixed at their root (a shared config staging path, a first-run seeder writing
into another test's root, a Windows startup storm, a test-parked environment flag read live), a
transcript no longer breaks on a message without metadata, a Chat history timer no longer fires
after unmount, and a dev-only warning names a viewport pinned by DevTools emulation.

## Known gaps

The Windows CLI installer copies only `biorouter.exe`, so `serve` cannot find its daemon there
yet. Two follow-up briefs cover it and the remaining hygiene items.
