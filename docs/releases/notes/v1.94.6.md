# Biorouter v1.94.6

This release fixes the problems found in a review of Biorouter on BioRouterBench and in reports from people running `biorouter serve` on remote hosts. Shell commands, unattended runs, custom system prompts and the secret guard behave more predictably, a served host keeps its access token out of logs, and a saved API key is never shown again. Bedrock calls use prompt caching, and a transient provider fault or an empty reply gets one retry. The desktop app gains a built-in browser you can browse with and the agent can drive with your permission, fn key dictation on macOS, a simpler Dictionary page, clearer page controls and a window that can narrow to a two-pane split.

## Running commands and unattended runs

The benchmark review is tracked in [#534](https://github.com/BaranziniLab/biorouter/issues/534). [#541](https://github.com/BaranziniLab/biorouter/issues/541) (rerun BioRouterBench with a stock-prompt, full-roster Biorouter profile) is a plan for the next run, not a rerun: see [the rerun plan](../../benchmarking/biorouterbench-stock-profile-rerun-plan.md).

- **Background shell jobs are readable, bounded and honest** ([#523](https://github.com/BaranziniLab/biorouter/issues/523), [#528](https://github.com/BaranziniLab/biorouter/issues/528), [#538](https://github.com/BaranziniLab/biorouter/issues/538)). Every background job writes a log file that any shell command can read, so a job is readable when `shell_status` is not granted. `shell_status` returns what a terminal would show instead of raw spinner frames, at most 100 lines and 8,000 characters per call. A job held open by a process that left it is still reported as running, with a note naming that process.
- **A foreground command ends when its shell exits** ([#536](https://github.com/BaranziniLab/biorouter/issues/536)), even when a process it started in the background still holds its output.
- **A command killed at the 240 second budget returns what it printed and is marked final** ([#537](https://github.com/BaranziniLab/biorouter/issues/537)). The model no longer reads "one retry is reasonable" for a call that would be killed again. The shell tool's description asks for a margin, under about 200 seconds, and a command that starts with a sleep as long as the budget is refused before it runs.
- **`biorouter run` says how it ended and exits by it.** A limit stop exits 3 with one line naming the limit ([#540](https://github.com/BaranziniLab/biorouter/issues/540)). `--require-file PATH` checks the files the run was asked for and exits 4 when one is missing ([#535](https://github.com/BaranziniLab/biorouter/issues/535)). A full disk no longer ends the run with exit 78: unsaved rows are held, retried and reported, with exit 5 when some were never saved ([#549](https://github.com/BaranziniLab/biorouter/issues/549)). The JSON output carries the stop reason, the counts and the wall time.
- **Unattended runs get an accurate prompt** ([#539](https://github.com/BaranziniLab/biorouter/issues/539)). A non-interactive run is told that nobody can answer or approve, to verify each requested file before the final reply, and that only the turn ends at a reply without a tool call. `--instructions FILE` keeps `--system`.
- **A call that needs an approval nobody can give is not called declined** ([#543](https://github.com/BaranziniLab/biorouter/issues/543)). The model is told the call was not run because nobody could approve it, and to continue another way. A scheduled run no longer waits for an approval it can never get. Redirect targets now end where the shell ends the word, so `2>/dev/null)` is no longer read as a write under `/dev`.
- **A repeated denial gets one more chance** ([#547](https://github.com/BaranziniLab/biorouter/issues/547), shipped earlier in this release's branch). The model is told once that the same call keeps being denied and can act on it before the run ends.
- **A custom system prompt composes with Biorouter's core** ([#544](https://github.com/BaranziniLab/biorouter/issues/544)). `BIOROUTER_SYSTEM_PROMPT_FILE_PATH` now stands in for the stock prompt and keeps the tool roster, each capability's instructions, the task rules, what the tool-output frame means and the safety rules. `BIOROUTER_SYSTEM_PROMPT_OVERRIDE_MODE=replace` restores the old behaviour. A file with nothing a reader can see in it counts as empty. See [Custom system prompts](../../agent-loop/custom-system-prompts.md).
- **A tool name the model gets slightly wrong is matched against the tools offered** ([#545](https://github.com/BaranziniLab/biorouter/issues/545)). A bare name such as `shell` that ends exactly one offered tool's name runs as that tool, and policies and hooks judge the full name. An unknown or ambiguous name, prefixed or not, is answered with the offered names it may have meant. Tools hidden from the chat are never named.
- **`biorouter run` shows the calls an `execute_code` script really ran** ([#525](https://github.com/BaranziniLab/biorouter/issues/525)), with their evaluated arguments, not only the labels the model wrote. Credentials are withheld and control characters dropped in those lines and in the call lines above them, even with `--debug`.

## Secret guard

- **A quoted here-document that only writes a file is read as data** ([#546](https://github.com/BaranziniLab/biorouter/issues/546)). R, Python or Markdown written with `cat > FILE <<'EOF'` is no longer refused for a `$` in its text, and a long prose body is no longer refused as too complex. A protected path inside the body is still refused, and the refusal now says the word came from a here-document body. See [Secret guard](../../security/secret-guard.md).
- **`.env` templates can be read** ([#522](https://github.com/BaranziniLab/biorouter/issues/522)). `.env.example`, `.env.sample`, `.env.template`, `.env.dist`, `.env.tpl`, `.env.defaults` and `.env.<name>.example` are no longer refused, so `cp .env.example .env` works. `.env`, `.env.local` and `.env.production` stay protected, a template that links to `.env` is judged as `.env`, and a project's `.biorouterignore` can still deny a template. A Todo item, or an `execute_code` script whose text names a protected file, is no longer refused for the mention; every call the script makes is still checked with its real arguments. Other tools' text keeps the full check.

## Browser access and provider keys

- **`biorouter serve` keeps its access token out of logs** ([#524](https://github.com/BaranziniLab/biorouter/issues/524)). The banner prints the full address only for a token made for this launch at a terminal, or with `--print-url`. Otherwise it prints the address without the token and names `biorouter serve url`, which shows the full address to the account that runs `serve`. The dictation messages for SSH sessions point to that command too.
- **Safer key entry on a served host** ([#526](https://github.com/BaranziniLab/biorouter/issues/526)). A page served over plain HTTP on a network address names HTTPS and an SSH or SSM tunnel to a loopback address before the host shell. `biorouter configure --provider <provider> --secret-stdin` saves a provider's key at a hidden prompt, or from stdin, checks it with the provider first and never echoes it. Both `biorouter configure` and that command warn when a `biorouter serve` on the host runs as another account, and say where that server reads its settings.
- **Saved API keys are never shown** ([#532](https://github.com/BaranziniLab/biorouter/pull/532)). A saved key appears as a fixed mask, and nothing can read it back: the key preview route is gone, and `/config/read` answers the mask for any key a provider or extension declares secret and nothing for a key it does not recognise. **Edit** opens an empty field for a replacement. If saving the replacement fails, the key that worked is kept. Editing a custom provider without a new key leaves the secret store alone.
- **A missing key names the store that was read** ([#521](https://github.com/BaranziniLab/biorouter/issues/521)). With `BIOROUTER_DISABLE_KEYRING` set, often inherited from a parent shell, a missing key says which file was read, that the keychain was not checked, and the two ways to fix it: unset the variable, or run `biorouter configure` to add the key to the file. Versa Bedrock and Versa Azure read their keys the same way, and a store that refused the read is reported as such rather than as a missing key.

## Providers

- **Bedrock sends prompt-caching checkpoints** ([#527](https://github.com/BaranziniLab/biorouter/issues/527)) on the Claude models AWS lists for prompt caching, for both `aws_bedrock` and `versa_bedrock`, so a long system prompt and tool list are no longer billed in full on every call. Other models get none. `BEDROCK_PROMPT_CACHING=false` turns them off. A gateway that refuses the checkpoints gets the request once more without them, and the provider stops sending them for that model.
- **One retry for an in-stream fault or an empty reply** ([#542](https://github.com/BaranziniLab/biorouter/issues/542)). A provider error frame inside a stream that is transient, such as a 408, 429 or 5xx, or an error finish with no explanation, is retried once instead of ending the turn. Credential, quota, content policy and other request errors still end it. An empty reply, with no text and no tool call, is asked for once more with a note only the model sees; a second empty reply ends the turn as a provider failure, so a headless run no longer exits 0 with the answer missing.
- **Streamed `reasoning_details` fragments are merged before replay** ([#548](https://github.com/BaranziniLab/biorouter/issues/548)), so an OpenRouter run no longer resends tens of thousands of entries on every request.
- The Google provider offers Gemini 4 Neon.

## Desktop app

- **Dictate with the fn key on macOS.** Hold fn to talk and let go to insert; double-tap fn for hands-free dictation and double-tap again to stop. Capture starts the moment fn goes down, so the first words are kept, and a single tap or fn with another key inserts nothing. An on-screen indicator shows while dictation records or finishes. With **Dictate into other apps** and **Use fn in other apps** on, fn dictates into other apps through the clipboard. The suggested Dictate to clipboard shortcut is now saved, and so registered, off macOS. macOS asks for Input Monitoring only from the button in Settings.
- **Dictation setup is polished.** The setup popover's install ring is centred, Save choice and Retry sit inline, and the speech model install rows in Settings are calmer. A retried install keeps the dictionary choice made at the first install.
- **The Dictionary page holds the dictionary.** Its options, including the agent's terms, both kinds of suggestion and **Find words** for recent chats, moved to **Settings > Models > Speech models**, opened from the **Dictionary settings** icon in the page's header. Both kinds of suggestion, words from your chats and words from your messages, are now on by default where you have not chosen. A choice you saved is kept, both can be turned off there, and private chats are never read for suggestions. The examples now read "UCSF or Biorouter".
- **Applications and Application Drafter.** The list of built apps is now **Applications**, and the builder is **Application Drafter**. Commands, tool names and saved settings keep their old names, so nothing needs to change.
- **Text size is Small, Standard and Large.** The default moved up one step to the new Standard. A size you saved before keeps the same look under its new name. A choice still applies when the browser's storage is blocked.
- **Page header buttons** are all one 28px size, and each primary names its object: New schedule, New workflow, Add extension, Add skill and Add terms.
- **The composer's working folder** shows a tooltip on hover. A click opens the folder picker on Home and in a new chat. Once a chat has messages the folder is fixed, and a click opens the folder access card. The **+** menu now has the model menu's width.
- **Home and the window.** The window can narrow to a two-pane split after the sidebar folds (its minimum width is now 721 px, down from 1048), and Home's composer narrows with it. Home's usage card shows only at its full width and steps aside, first dropping its heat map, before it can touch the composer.
- **Knowledge page.** The graph canvas is a rounded inset panel, with no stray line along its top.
- **Crew.** The You row at the bottom of Crew lines up with the app sidebar's footer.
- **Bringing Biorouter forward.** The menu bar icon shows existing macOS windows in front of the active app and no longer moves them ([#550](https://github.com/BaranziniLab/biorouter/pull/550)). It, the tray items, Focus Biorouter Window, the Dock icon, Check for Updates, deep links and extension files act only on chat windows, never on the hidden dictation windows, and open a chat window when none is open.
- **Long model menus scroll** again where they open over other content ([#531](https://github.com/BaranziniLab/biorouter/pull/531)).
- **Biorouter Copilot's helper is updated to upstream Open Computer Use 1.1.5** (from 0.3.5). On a Mac it reads Chrome and Electron pages on the first look, finds apps faster, never reads a password field, does not press a disabled control, and releases the mouse button when a click or drag fails partway. On Windows it refuses input to an elevated or unresponsive window instead of reporting success, finds Store apps and secondary windows, and sends a shortcut such as Ctrl+S as real keys once you allow Copilot to use your desktop. On Linux it refuses to write a read-only field. The ten Copilot tools and their arguments are unchanged; upstream's new query and select text tools, background keyboard delivery and Locked Use, which unlocks a locked Mac, are not included.

## Built-in browser

The side panel's web view becomes the **Biorouter Browser**: a browser for ordinary browsing, which the agent can also drive once you allow it. See [The built-in browser](../../desktop-ui/built-in-browser.md).

- **A browser you can use.** A link in a chat opens its page in the side panel at once. Cmd or Ctrl click, or a middle click, opens your default browser instead, and **Settings > Chat > Display > Open links in** swaps the two. Sign-in pages load, `target=_blank` links open as panel tabs and sign-in popups as small windows, downloads go through the save dialog (marked as downloaded on macOS), and PDFs open in the tab. The address field searches for text that is not an address and suggests pages from your own history and bookmarks. The ⋯ menu holds zoom, find in page, bookmarks and **Clear site data**. Logins stay in one browser profile that every chat shares. An intranet or `localhost` page opens when you go to it, but a public page cannot reach one on its own, and Biorouter's own daemon port is refused. A certificate error fails closed, offering your default browser. Typing a `file:`, `javascript:` or similar address is refused with one line under the bar.
- **The agent can use it, with your permission.** The Biorouter Browser capability, on by default, gives the agent fifteen `browser_*` tools: open, navigate, tabs, snapshot (an accessibility tree with element references), read as Markdown, screenshot, scroll, hover, wait, click, fill, type, press, select and answer a page dialog. Reading pages needs your approval once per chat. Acting needs it once per request, or for the chat with **Allow for this chat**. Acting covers opening an address, back, forward and reload, following a link to another site, clicking anything other than a link, typing, choosing, submitting and downloading. The cards appear above the composer in every permission mode, and the model can never approve them. While the agent drives, the bar reads "Biorouter is browsing" with **Stop**. That Stop, like Copilot's, ends both capabilities' grants and cancels the operation in flight.
- **What the agent cannot do.** It sees only the tabs it opened; a tab you opened stays private until you press **Share with agent**, and the agent can read a shared tab but not drive it. It never types into password, verification code or card fields, runs page JavaScript or uploads files, and page text and screenshots reach the model marked as untrusted. A public chat cannot send it to a private network or loopback address. It works only while its chat is on screen in the desktop app: the tools are withheld in `biorouter serve`, in a CLI session that runs its own daemon, and in subagents.
- **Beside Biorouter Copilot.** Web pages go to the Biorouter Browser. Native apps, the operating system, file dialogs and your own Chrome or Safari window go to Copilot. Both tool sets carry the same routing sentence, and a declined browser grant is never moved to Copilot. Chats saved before this release are offered the browser when they open, unless you turned it off for every chat. The Web & Documents capability is now described as fetching web pages, so only the Biorouter Browser reads as a browser.
- **Import from Chrome, only when you ask.** From the browser's first-use card, its ⋯ menu or **Settings > App > Browser**, choose a Chrome profile and any of: logins (cookies, for every site or the sites you pick), bookmarks, history from the last 90 days, and settings (search engine, languages and default zoom). Biorouter then asks in a dialog of its own, with Cancel as the default, and on macOS the system asks you to allow access to Chrome Safe Storage. Saved passwords, payment data, the cache, site storage and extensions are never imported. Chrome's key is read by a helper that only the app itself can run; the secret guard refuses any command that names it, and Chrome's cookie, password and card files and the browser's own cookie file are on the secret guard's floor. **Remove imported data**, in Settings and in the import summary, asks first, then signs you out of what the import logged in to and removes its bookmarks, history and settings.

## Known limitations

- The fn key needs Input Monitoring. Its behaviour with a physical key on a signed build, and the dictation indicator on Windows and Linux, were not verified by automated tests. A single fn tap may turn the microphone on for less than 300 ms before it is discarded.
- `biorouter configure` finds a `biorouter serve` run by another account from the process list. A host that hides other accounts' processes shows no warning.
- A full-disk `biorouter run` holds its unsaved rows in memory only, and holds only message and usage writes.
- Chrome on Windows locks its logins to Chrome (app-bound encryption, Chrome 127 and later), so the import brings bookmarks, history and settings there but no logins. The Linux path that reads Chrome's key from the Secret Service has been type-checked but not run on Linux.
- The Biorouter Browser does not browse in the background: an agent's browser call fails while its chat is not on screen. At the panel's default width many sites show their phone layout; widen the panel or zoom out from the ⋯ menu, which is remembered per site.
- In the release test run, an agent's click on a button that opened a page `alert`, `confirm` or `prompt` waited for the 30 second deadline instead of reporting the dialog. The automated Electron tests see the dialog answered at once, so the cause is not yet known.
- The updated Copilot helper's Windows and Linux builds are checked by the automated fixtures, not yet on a person's desktop. On Windows, a shortcut sent as real keys brings its window to the front first.
