# Biorouter v1.94.6

This release fixes the problems found in a review of Biorouter on BioRouterBench and in reports from people running `biorouter serve` on remote hosts. Shell commands, unattended runs, custom system prompts and the secret guard behave more predictably, and a served host keeps its access token out of logs. The desktop app gains fn key dictation on macOS, a simpler Dictionary page, clearer page controls and a window that can narrow to a two-pane split.

## Running commands and unattended runs

The benchmark review is tracked in [#534](https://github.com/BaranziniLab/biorouter/issues/534). [#541](https://github.com/BaranziniLab/biorouter/issues/541) (rerun BioRouterBench with a stock-prompt, full-roster Biorouter profile) is a plan for the next run, not a rerun: see [the rerun plan](../../benchmarking/biorouterbench-stock-profile-rerun-plan.md).

- **Background shell jobs are readable, bounded and honest** ([#523](https://github.com/BaranziniLab/biorouter/issues/523), [#528](https://github.com/BaranziniLab/biorouter/issues/528), [#538](https://github.com/BaranziniLab/biorouter/issues/538)). Every background job writes a log file that any shell command can read, so a job is readable when `shell_status` is not granted. `shell_status` returns what a terminal would show instead of raw spinner frames, at most 100 lines and 8,000 characters per call. A job held open by a process that left it is still reported as running, with a note naming that process.
- **A foreground command ends when its shell exits** ([#536](https://github.com/BaranziniLab/biorouter/issues/536)), even when a process it started in the background still holds its output.
- **A command killed at the 240 second budget returns what it printed and is marked final** ([#537](https://github.com/BaranziniLab/biorouter/issues/537)). The model no longer reads "one retry is reasonable" for a call that would be killed again. The shell tool's description asks for a margin, under about 200 seconds, and a command that starts with a sleep as long as the budget is refused before it runs.
- **`biorouter run` says how it ended and exits by it.** A limit stop exits 3 with one line naming the limit ([#540](https://github.com/BaranziniLab/biorouter/issues/540)). `--require-file PATH` checks the files the run was asked for and exits 4 when one is missing ([#535](https://github.com/BaranziniLab/biorouter/issues/535)). A full disk no longer ends the run with exit 78: unsaved rows are held, retried and reported, with exit 5 when some were never saved ([#549](https://github.com/BaranziniLab/biorouter/issues/549)). The JSON output carries the stop reason, the counts and the wall time.
- **Unattended runs get an accurate prompt** ([#539](https://github.com/BaranziniLab/biorouter/issues/539)). A non-interactive run is told that nobody can answer or approve, to verify each requested file before the final reply, and that only the turn ends at a reply without a tool call. `--instructions FILE` keeps `--system`.
- **A call that needs an approval nobody can give is not called declined** ([#543](https://github.com/BaranziniLab/biorouter/issues/543)). The model is told the call was not run because nobody could approve it, and to continue another way. A scheduled run no longer waits for an approval it can never get. Redirect targets now end where the shell ends the word, so `2>/dev/null)` is no longer read as a write under `/dev`.
- **A repeated denial gets one more chance** ([#547](https://github.com/BaranziniLab/biorouter/issues/547), shipped earlier in this release's branch). The model is told once that the same call keeps being denied and can act on it before the run ends.
- **A custom system prompt composes with Biorouter's core** ([#544](https://github.com/BaranziniLab/biorouter/issues/544)). `BIOROUTER_SYSTEM_PROMPT_FILE_PATH` now stands in for the stock prompt and keeps the tool roster, each capability's instructions, the task rules, what the tool-output frame means and the safety rules. `BIOROUTER_SYSTEM_PROMPT_OVERRIDE_MODE=replace` restores the old behaviour. A file with nothing a reader can see in it counts as empty. See [Custom system prompts](../../agent-loop/custom-system-prompts.md).
- **A tool name the model gets slightly wrong is matched against the tools offered** ([#545](https://github.com/BaranziniLab/biorouter/issues/545)). A bare name such as `shell` that ends exactly one offered tool's name runs as that tool, and policies and hooks judge the full name. An unknown or ambiguous name, prefixed or not, is answered with the offered names it may have meant. Tools hidden from the chat are never named.
- **`biorouter run` shows the calls an `execute_code` script really ran** ([#525](https://github.com/BaranziniLab/biorouter/issues/525)), with their evaluated arguments, not only the labels the model wrote. Credentials are withheld and control characters dropped in those lines and in the call lines above them, even with `--debug`.

## Secret guard

- **A quoted here-document that only writes a file is read as data** ([#546](https://github.com/BaranziniLab/biorouter/issues/546)). R, Python or Markdown written with `cat > FILE <<'EOF'` is no longer refused for a `$` in its text, and a long prose body is no longer refused as too complex. A protected path inside the body is still refused, and the refusal now says the word came from a here-document body. See [Secret guard](../../security/secret-guard.md).
- **`.env` templates can be read** ([#522](https://github.com/BaranziniLab/biorouter/issues/522)). `.env.example`, `.env.sample`, `.env.template` and similar files are no longer refused, so `cp .env.example .env` works. `.env` itself stays protected. A checklist item or an `execute_code` comment that mentions a protected file is no longer refused as if it read it.

## Browser access and provider keys

- **`biorouter serve` keeps its access token out of logs** ([#524](https://github.com/BaranziniLab/biorouter/issues/524)). The banner prints the full address only for a token made for this launch at a terminal, or with `--print-url`. Otherwise it prints the address without the token and names `biorouter serve url`, which shows the full address to the account that runs `serve`. The dictation messages for SSH sessions point to that command too.
- **Safer key entry on a served host** ([#526](https://github.com/BaranziniLab/biorouter/issues/526)). A page served over plain HTTP on a network address names HTTPS and an SSH or SSM tunnel to a loopback address before the host shell. `biorouter configure --provider <provider> --secret-stdin` saves a provider's key at a hidden prompt, or from stdin, checks it with the provider first and never echoes it. Both `biorouter configure` and that command warn when a `biorouter serve` on the host runs as another account, and say where that server reads its settings.
- **Saved API keys are never shown** ([#532](https://github.com/BaranziniLab/biorouter/pull/532)). A saved key appears as a fixed mask, and nothing can read it back. If saving a replacement fails, the key that worked is kept.
- **A missing key names the store that was read** ([#521](https://github.com/BaranziniLab/biorouter/issues/521)). With `BIOROUTER_DISABLE_KEYRING` set, the CLI says which file it read, that the keychain was not checked, and the two ways to fix it.

## Providers

- **Bedrock sends prompt-caching checkpoints** ([#527](https://github.com/BaranziniLab/biorouter/issues/527)) on the Claude models AWS lists for prompt caching, for both `aws_bedrock` and `versa_bedrock`, so a long system prompt and tool list are no longer billed in full on every call. `BEDROCK_PROMPT_CACHING=false` turns them off.
- **One retry for an in-stream fault or an empty reply** ([#542](https://github.com/BaranziniLab/biorouter/issues/542)). A provider error frame inside a stream that is transient, such as a 429 or a 5xx, is retried once instead of ending the turn.
- **Streamed `reasoning_details` fragments are merged before replay** ([#548](https://github.com/BaranziniLab/biorouter/issues/548)), so an OpenRouter run no longer resends tens of thousands of entries on every request.
- The Google provider offers Gemini 4 Neon.

## Desktop app

- **Dictate with the fn key on macOS.** Hold fn to talk and let go to insert; double-tap fn for hands-free dictation and double-tap again to stop. Capture starts the moment fn goes down, so the first words are kept, and a single tap or fn with another key inserts nothing. An on-screen indicator shows while dictation records or finishes. With **Dictate into other apps** and **Use fn in other apps** on, fn dictates into other apps through the clipboard. The suggested Dictate to clipboard shortcut is now saved, and so registered, off macOS. macOS asks for Input Monitoring only from the button in Settings.
- **Dictation setup is polished.** The setup popover's install ring is centred, Save choice and Retry sit inline, and the speech model install rows in Settings are calmer. A retried install keeps the dictionary choice made at the first install.
- **The Dictionary page holds the dictionary.** Its options, including the agent's terms, both kinds of suggestion and **Find words** for recent chats, moved to **Settings > Models > Speech models**, opened from the page's settings icon. Suggestions from your chats and messages are now on by default for a new dictionary. A choice you saved is kept, and both can be turned off there. The examples now read "UCSF or Biorouter".
- **Applications and Application Drafter.** The list of built apps is now **Applications**, and the builder is **Application Drafter**. Commands, tool names and saved settings keep their old names, so nothing needs to change.
- **Text size is Small, Standard and Large.** The default moved up one step to the new Standard. A size you saved before keeps the same look under its new name. A choice still applies when the browser's storage is blocked.
- **Page header buttons** are all one 28px size, and each primary names its object: New schedule, New workflow, Add extension, Add skill and Add terms.
- **The composer's working folder** shows a tooltip on hover. A click opens the folder picker on Home and in a new chat. Once a chat has messages the folder is fixed, and a click opens the folder access card. The **+** menu now has the model menu's width.
- **Home and the window.** The window can narrow to a two-pane split after the sidebar folds, and Home's composer narrows with it. Home's usage card shows only at its full width and steps aside, first dropping its heat map, before it can touch the composer.
- **Knowledge page.** The graph canvas is a rounded inset panel, with no stray line along its top.
- **Crew.** The You row at the bottom of Crew lines up with the app sidebar's footer.
- **Bringing Biorouter forward.** The menu bar icon shows existing macOS windows in front of the active app and no longer moves them ([#550](https://github.com/BaranziniLab/biorouter/pull/550)). It, the tray items, Focus Biorouter Window, the Dock icon, Check for Updates, deep links and extension files act only on chat windows, never on the hidden dictation windows, and open a chat window when none is open.
- **Long model menus scroll** again where they open over other content ([#531](https://github.com/BaranziniLab/biorouter/pull/531)).

## Known limitations

- The fn key needs Input Monitoring. Its behaviour with a physical key on a signed build, and the dictation indicator on Windows and Linux, were not verified by automated tests. A single fn tap may turn the microphone on for less than 300 ms before it is discarded.
- `biorouter configure` finds a `biorouter serve` run by another account from the process list. A host that hides other accounts' processes shows no warning.
- A full-disk `biorouter run` holds its unsaved rows in memory only, and holds only message and usage writes.
