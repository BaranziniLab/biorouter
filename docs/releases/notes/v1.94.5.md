# Biorouter v1.94.5

This release adds local voice dictation, clearer controls for longer tasks, browser provider setup and updates, and compact split panes. It refreshes provider models and fixes reliability problems across the desktop app, browser and command line since v1.94.1.

## Usage limits

**Monthly budgets that previously only drove the Usage gauge are now enforced.** If your configuration already contains `monthly_token_limit` or `monthly_dollar_limit`, upgrading activates that limit. Biorouter pauses before another model request when the monthly limit is reached or the next request is estimated to exceed it. Raise or remove the limit in **Settings > App > Usage** to continue. This change comes from [#483](https://github.com/BaranziniLab/biorouter/pull/483).

- Set dollar or billed-token limits for one chat, a default for new chats, or the local calendar month. A chat's limit includes its subagents. Costs include more background and late-arriving usage, and limit-stopped work reports failure.
- Limits are spending controls, not a provider billing cap. Concurrent requests can jointly exceed a limit, some side calls are counted without being blocked, and dollar limits cannot stop unpriced models. See [Usage limits](../../agent-loop/usage-limits.md).

## Dictation and longer tasks

- Dictate into the composer, terminal chats, Crew messages and a `biorouter serve` browser. Review the transcribed text before sending. Install a speech model in **Settings > Models > Speech models**; transcription runs on the backend machine. The CLI also offers `biorouter dictate` and `biorouter transcribe`.
- Manage personal terms and optional correction suggestions in Dictionary. Message learning remains opt-in. Audio decoding and Linux microphone detection handle unavailable or damaged inputs more carefully.
- Follow background subagents and orchestration phases from the chat summary and History. Optional decision models support typed checks, monitors and phase gates, with their privacy tier and usage included. A default worker model can differ from the main model.

## Chats and compact panes

- The composer uses a single **+** popover for attachments, extensions, skills and knowledge. Per-chat switches remain with their chat, including an unsaved draft tab.
- Small split panes show a compact placeholder. Grow actions restore room; **Merge panes** brings tabs together. Chats stay mounted, terminal sessions survive layout changes, and transcript scroll ownership is retained through reflow. Opening a chat into a compact pane does not widen it automatically.
- Stopping a running turn records **The person canceled this turn before it finished.** History retains the note, and the model sees it on the next turn. It is shared by desktop and browser Stop, classic and full-screen terminal chat, session cancel and ACP cancel. Steering a running turn and canceling after completion do not add it.

## Browser access and tools

- The person at a `biorouter serve` page can configure the host's providers and default model, then update and restart the service at the same address. Tunnel changes require proof of the person's action, and the page follows the host's current default.
- Browser Diverge opens the created branch in the current interface. Served file previews apply secret-file checks and text redaction. A browser no longer offers the desktop-only in-app terminal button.
- Requests that require an answer in the desktop app show that guidance in the browser.
- The classic terminal answers `/model` locally with current-model information and help. A daemon's first turn restores that chat's saved extensions, and an unanswered knowledge query returns an error instead of empty success.
- Built apps enforce their declared state schema, file modes and approvals, restore history and show limit failures. Exports exclude credentials; host-folder mounts remain unavailable. Skill imports handle large repositories without overwriting shipped skills. Corrupt-source ingestion and failed figure-library downloads report clearer errors.

## Providers and model compatibility

- Refresh bundled defaults, catalogues, model specifications and supported prices. Direct Anthropic defaults to Claude Opus 5.5, OpenAI to GPT-6.2 Astra, and Google to Gemini 4 Hydrogen. Versa API Bedrock puts Opus 5.5, Sonnet 5.5 and Haiku 5.5 ahead of older models. Public Azure and institutional deployments keep their separate availability rules.
- Codex and GitHub Copilot use eligible account catalogues for fresh choices. Explicit saved models remain selected. Copilot keeps a successful empty catalogue empty and uses its documented fallback only when discovery is unavailable. Claude Code retains its own installed-CLI and plan requirements.
- Update Kimi, Mistral, MiMo, DeepSeek and Mercury choices. Baseten adds optional Kimi K3.1 Pro with host-specific context and prices while retaining GLM 5.3 as its default; older catalogue data cannot replace a newer bundle.
- Preserve supported native thinking, signatures and tool history. Opaque reasoning details are replayed only to their originating provider; ambiguous older details are omitted. Availability, context and prices remain specific to each provider, account, region and deployment. A catalogue entry does not establish entitlement.

## Workflow and extension reliability

- Scheduled workflows honor retry checks and report exhaustion as failure. Deleting a workflow also removes its future schedules, without stopping an already running job.
- Failed extension upgrades restore the previous working package or report a retained recovery backup. Update results count successes accurately. Overlapping installs cannot roll back another completed upgrade, and rollback preserves previously stored credentials.
- Extraction refuses existing links that would redirect writes outside the installation tree. Deleting a marketplace package removes its stale saved-chat tool entries. These repairs do not change an extension's documented current-user execution authority.
- Stopped or answered input forms stay settled after rerender and reload. Memory tools and coding-agent bridges retain per-write approval and inspector details. Plain Crew setup preserves an explicit **Off** choice.

## Known limitations

- Deleting a long-context chat can lower the month's recomputed dollar total; token totals remain retained. Budget concurrency and unpriced-model limits still apply.
- Some multi-pane layouts merge on reload. An approval already waiting when a pane becomes compact does not make a new waiting announcement.
- Enter during a running classic-terminal turn can insert a newline. Some optional extension-secret prompts reject an empty answer, TIFF previews can fail, and unattended schedules still need all required values supplied in advance.
- Native VoiceOver coverage and real-speech dictation accuracy are not established by automated fixtures. The final report retains the other native, account and owner-present verification limits.
